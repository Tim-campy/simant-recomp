# Mod API

API version: **0.38**. Mods override data (database objects, `data/*.json` — **by key** since 0.26 —, loose files) and, since 0.12, can carry sandboxed **Lua scripts** (section "Lua scripts"); since 0.17, scripts can have a menu, a panel and actions on the game (for testing, like the cheat mod in `exemplos/mods/trapacas/`); since 0.26, hooks inside the tick, scent writes, castes, ants and food in the nests, and state stored alongside the save; since 0.35, the original SimAnt's texts no longer come in the port's `data/*.json`, but from the user's installation (section "Texts from the original"); since 0.36, the mini map uses an offset measured on the first opening.

## Structure

Each mod is a directory inside `mods/`:

```
mods/
  meu-mod/
    mod.json
    objetos/<tipo>/<id>.bin     (optional) replaces an object of the original database
    data/<arquivo>.json         (optional) merged by key over a file in the port's data/ (API 0.26)
    <arquivo>.lua               (optional, API 0.12) script listed in "scripts" in mod.json
```

`mod.json`:

```json
{ "nome": "meu-mod", "versao": "1.0", "dependencias": ["outro-mod"], "scripts": ["principal.lua"] }
```

`scripts` is optional (API 0.12): list of the mod's `.lua` files, in load order, with paths relative to the mod's directory (subfolders are allowed; `..` and absolute paths are not).

## Rules

- **Database objects:** `objetos/<tipo>/<id>.bin` replaces the object (type, id) of any original database. The content must be **decompressed**, in the format described in `docs/spec/formatos/`. Example: `objetos/2/2000.bin` swaps the top half of the logo (bitmap, see `bitmap.md`).
- **Data files:** the mod's `data/<nome>` is **merged by key** over the file of the same name in `data/` (API 0.26; up to 0.25 it replaced the whole file). Merge rules (`Recursos::dados`, `engine/src/recursos.rs`):
  - **objects merge:** each key the mod brings is merged into the key of the same name, at any depth; keys the mod does not bring stay as in the port. A mod can bring only what changes, for example `data/quintal.json` = `{"regras": {"gato_chance": 64}}`;
  - **lists replace:** a list from the mod replaces the whole list (there is no item-by-item merge: key lists, tables such as `turn_tab`, `dx8`...);
  - **values replace:** numbers, strings, booleans and `null` replace the value; a different type (an object in place of a number, etc.) also replaces it;
  - **`"_substituir": true`** inside an object of the mod replaces the whole object instead of merging (the mark is removed before the port reads it). It serves to **remove** keys: drop a key from a name → action map, or go back to the old whole-file behavior with `"_substituir": true` at the top;
  - **several mods:** in mod order (dependencies first, then alphabetical), each one is merged over the result of the previous one; a file that exists only in the mod comes in whole.
  - Format errors after the merge cite the file and the mods that merged it.

  Files available in milestone 1:
  - `paleta.json`: the 16 colors;
  - `telas.json`: opening sequence (windows, loose bitmaps, duration in ticks, close triggers);
  - `interface.json`: client area geometry (ribbon, window border, system colors);

  - `navegacao.json` (API 0.3): keys (`teclas`: SDL key name, `ctrl`/`shift`/`alt`, `acao`), ribbon buttons (`botoes_faixa`: object name → action), repeat of the scroll bar arrows (`repeticao`) and initial view when opening a save (`posicao_inicial`: `ao_carregar` or `salva`). Actions: `linha_acima`, `linha_abaixo`, `linha_esquerda`, `linha_direita`, `pagina_acima`, `pagina_abaixo`, `pagina_esquerda`, `pagina_direita`, `superficie`, `ninho_preto`, `ninho_vermelho`;

    - `ninho.json`: nest ants, eggs and queen (ninho.md, ciclo-de-vida.md);
    - `amarela.json`: the yellow ant; also applies when another part kills it, feeds it or fights it (formiga-amarela.md);
    - `geracao.json`: world generation and the directions of `_AddFood` (geracao-mundo.md; the sine comes from object 9/1000 of the database);
    - `comum.json` (API 0.20): the tables the original has **only once** and several parts use — `dx8`/`dy8` and `dx9`/`dy9` (`_Dx8`, `_Dx9`), `turn_tab` (`_TurnTab`), `grupo_sem_carga` (`_UnCarryCaste`), `modos_operaria`/`modos_soldado`/`modo_por_grupo` (`_ModeTabWB`, `_ModeTabSB`, `_CasteModeTabB`), `sow_tab` (`_SowTab`), `classe_luta`, `matriz_luta`, `borda_buraco` and `borda_formiga_leao`. Changing a table here changes the whole game (for example, `classe_luta` applies to fights on the surface, in the nests and of the yellow ant). To change the rule for the whole game, move the table to a `comum.json` in the mod and remove it from the part's file. The files are validated on load (directions in −1..1, turn directions in 0..7, fight classes in 0..3, `regras.gato_chance` a power of 2...): an invalid value prevents the game from starting, with the error message.

- **Texts from the original** (API 0.35): the port's `data/*.json` do not carry SimAnt's texts (phrases, titles, file names, bitmap pieces from the executable); in place of each one goes a **reference** to its source in the user's installation, which `Recursos::dados` (`engine/src/recursos.rs`, `Referencia`) replaces with the text **after** the mods are merged. Forms:
  - `{"banco": "SHARED", "tipo": 4, "id": 1000, "indice": 9}` — string `indice` (from 0) of the type 4 string list (`docs/spec/formatos/banco-dat-ndx.md`);
  - `{"banco": "WINGANT", "tipo": 0, "id": 19, "objeto": 1}` — text of object `objeto` of the window layout (title, type 18, or text, types 5, 9, 16 and 17; `docs/spec/formatos/janela.md`);
  - `{"exe": "SIMANTW.EXE", "segmento": 10, "offset": "0x014b"}` — ASCIIZ text in the segment of the NE executable (numbering from `SIMANTW.SYM`: 10 = DGROUP, selector 1048; `offset` in hexadecimal as a string or a number); optional `"tamanho": n` (exactly `n` bytes) and `"pecas_8x8": [nomes]` (8 × 8 bitmap pieces, 16 bytes each, in the executable's order, become an object name → 8 lines of `.`/`#`/`o`; `null` skips a piece);
  - `{"hlp": "SIMANT.HLP", "campo": "titulo"}` — title of the help file.

  In all of them, optional `"formato"` with `{}` in place of the text (e.g. `"{} Help - SIMANT.HLP"`); keys starting with `_` are comments; unknown keys are an error. The original's bytes become Latin-1 characters. An object is a reference if it has `exe` + `segmento`, `banco` + `tipo` + `id`, or `hlp`. The named database is looked up first in the mods' `objetos/`, then among the open databases (`jogo.json`) and, if it is not among them, in the game folder; the executable and the `.HLP` are loose files (a mod can replace them in `arquivos/`). A reference that does not resolve prevents the file from loading, with the key's path and the source in the message.

  **A mod can still bring the text**: a string in place of the reference replaces it through the by-key merge (values replace objects), so mods that carried these texts (up to 0.34) keep working unchanged. A mod can also bring only part of the reference, for example `{"titulos": [...]}` with other references, or `{"faixa": {"marcador_posto": {"offset": "0x01bc"}}}` to use another text from the same segment. Keys that are references today: `mensagens.json` → `faixa.velocidade`, `faixa.marcador_posto`, `faixa.marcador_ausente`; `dialogos.json` → `caixa_mensagem.titulo_load`, `pergunta_load`, `titulo_quit`, `titulo_mensagem`, `salvo`, `arquivo.titulo_abrir`, `titulo_salvar`, `texto_tipo`, `campo_inicial`; `janelas.json` → `castas.titulo`, `tarefas.titulo`, `historico.titulo`; `quintal_mapa.json` → `titulos`, `balao_menino.pecas`; `tutorial_arquivo.json` → `nome`, `titulo`; `barra_menus.json` → `texto_pausa`; `moldura_principal.json` → `texto`; `ajuda.json` → `titulo`. The Windows 3.1 labels (system menu, Yes/No/OK/Cancel buttons, common file dialog labels, WinHelp menus and dialogs) remain as text in the port (`docs/lancamento.md` §6).
- **Loose game files:** `arquivos/<nome>` replaces a file in the game folder read by the port (the fonts `font1`–`font4` and `FONTRES.FON`; from API 0.6, also paths with a subfolder, such as `arquivos/sound/gamethme.mid`, case-insensitive).
- **Order:** mods are sorted so that each one comes after its dependencies; among independent mods, the order is alphabetical. If two mods override the same thing, the last one wins.
- **Errors:** a missing dependency, a duplicate name or a dependency cycle prevent the game from starting, with an error message.
- The original game files are never modified.

## Lua scripts (API 0.12)

A script is Lua 5.4 code that runs in a sandbox and talks to the game only through the functions below. Implementation: `engine/src/scripts.rs`; full example in `exemplos/mods/exemplo-lua/` (outside `mods/`, so it is not active by default).

### Loading and life cycle

- Each mod with `"scripts"` gets **a Lua machine of its own**: its files run in order on the same machine (they share globals); different mods cannot see each other.
- The order among mods is the same as for data (dependencies first, then alphabetical): for the same hook, the mod that comes first is called first.
- Scripts start over from scratch on each game (new game, Load). Since 0.26, a mod can store a table of its own alongside the save (`ao_salvar`/`ao_carregar`, section "State in the save"); Lua globals do not go into the save.
- Mods are chosen as for data: all those in `--mods DIR` (default `mods/` in the port's folder) are active, except those turned off by the player (`--desligar-mods NOME,NOME` or the launcher's checkboxes; names from `mod.json`). An enabled mod that depends on a disabled one is an error, like a missing dependency. This does not change the API: it is the choice of which folders to load.

### Hooks

The script defines **global** functions with these names (in the file body or inside `ao_iniciar`); only the defined hooks are called.

| Hook | When |
|---|---|
| `ao_iniciar(estado)` | Once, when the game starts (on Load, after `_FullCount`). |
| `antes_do_tick(estado)` | Before each simulation tick (`_DoAntSim`). |
| `depois_do_tick(estado)` | After each tick. |
| `ao_menu(indice, texto, estado)` | (API 0.17) The player chose item `indice` (from 1, counting separators) of the mod's menu (`definir_menu`). |
| `ao_evento(evento, estado)` | For each request from the rules to the interface, before the interface handles it. `evento.tipo` is `"som"`, `"musica"`, `"mensagem"` (with `id`), `"mensagem_faixa"` (with `lista`, `indice`), `"tema_do_ninho"`, `"fim_de_jogo"`, `"centralizar_na_amarela"` (since 2026-10-18 with `plano`, `x`, `y`: the yellow ant's position at the moment of the request; there can be more than one in the same tick) or, since 0.16, `"espera"` (with `ms`: an animation of the tick waits this long between two frames; the interface delays the following effects); since 0.18, `"animacao"` (with `codigo` — 0 fight, 1–9 death, 10 shock, −1 madness, since 0.37 −2 egg stages on rebirth and −3 when founding a colony —, `plano`, `quadros` and `espera_ms`: a yellow ant animation; the simulation stays stopped for `espera_ms × (quadros − 1)` ms while the edit window shows the frames); since 0.22, `"quadro_amarela"` (with `imagem`: `_YellowDialog`, trophallaxis is 9110) and `"escolher_colonia"` (`_SpecialXfer`: the player is going to choose another black colony in the yard); since 0.24, `"dialogo_aranha"` (with `texto`: `_SpiderDialog`, the spider ate the yellow ant; the text already drawn at random, SHARED type 4); since 0.25, `"quadro_amarela"` also with `indice` (−1 on trophallaxis, 0 on death 9100, 1 or 2 on rebirth 9101), `"quadro_formiga_leao"` (`_LionDialog`) and `"animacao_vitoria"` (`_DrawSimPayoff`). |
| `ao_salvar(estado)` | (API 0.26) File → Save/Save As (and `--salvar`), after writing the `.ANT`: returns the mod's table that goes into the side file, or `nil`. Section "State in the save". |
| `ao_carregar(dados, estado)` | (API 0.26) On Load, right after `ao_iniciar`, with the table the mod saved (only if the side file has data from this mod). |
| `antes_<parte>(estado)`, `depois_<parte>(estado)` | (API 0.26) **Inside** the tick, right before and right after the part (table below). |

`antes_do_tick`/`depois_do_tick` run **outside** the tick (before and after it). Without any mod with a script, the game loop is exactly the same as before (the original's tick vectors stay identical).

#### Hooks inside the tick (API 0.26)

Each part is a subroutine of `_DoAntSim` (simulacao-visao-geral.md §5); the order is **the original's** and does not change:

| Part | Original routine | Note |
|---|---|---|
| `quintal` | `_DoSimYard` | every tick |
| `agua` | `_DoWater` | every tick |
| `formigas_leao` | `_DoAntLions` | every tick |
| `aranha` | `_MoveSpider` | every tick |
| `lagarta` | `_DoPillar` | only on ticks with odd `_Cycle` |
| `estrategia` | `_GetStrategy` (`_SetCasteProd`, `_SetModeProd`) | every tick |
| `superficie` | `_DoAntSimA` (list A) | every tick |
| `ninho_preto` | `_DoAntSimB` | every tick |
| `ninho_vermelho` | `_DoAntSimR` | every tick |
| `amarela` | `_DoAntSimY` | every tick |
| `lider_vermelha` | `_MakeRedInitiator` | only when no red ant is in mode 19 |
| `movimento_amarela` | `_DoAntMoveY` | every tick |
| `conselhos` | `_Feedback` | at the end of the tick and also inside `_FullCount` (every 64 ticks, at the start of the tick) |

Example: `function antes_ninho_preto(estado) ... end` runs after `_DoAntSimA` and before `_DoAntSimB`. Periodic feeding (`_FeedAnts`), the upkeep of scents and counters (`_DoSmells`, `_CountAnts`, `_HistUpdate`) and the end of the tick have no hooks.

- **Writes** made in a part hook take effect immediately: the next part already sees them. **Actions** (requests) made in a part hook only run **after the whole tick**, before `depois_do_tick`.
- **Cost:** part hooks are only called if some active mod defines at least one of them; otherwise the tick is called as before, with no extra layer. With them, each defined hook costs one Lua call per tick (creating the `estado` object and the call; on the order of microseconds, plus whatever the script does), with the same instruction and time limits as any hook. A script that only reads does not change the game (test `ganchos_de_parte_que_so_leem_nao_mudam_o_jogo`, 300 ticks of `QUICK2.ANT`).
- An error in a part hook turns the mod off like any other error; the tick continues with the other parts.

### State in the save (API 0.26)

The original's `.ANT` has no field for mods, and the port does not change it (the original keeps reading the save normally). Each mod's state goes into a **side file** in the same folder, named after the save plus `.mods.json` (`JOGO.ANT` → `JOGO.ANT.mods.json`).

- **Saving:** after writing the `.ANT` (File → Save, Save As, the save before Load or Quit, `--salvar`), the port calls `ao_salvar(estado)` of each active mod that defines it. The returned value (a table, or `nil` = nothing to store) goes to JSON: `nil`, booleans, finite numbers, UTF-8 strings and tables — a 1..n list without holes becomes a list, a table with only string keys becomes an object (an empty one becomes an object). Functions, userdata, mixed keys (numbers and strings), lists with holes, `NaN`/infinities, more than 32 levels or more than 1 MiB of JSON per mod are an error (they turn the mod off, and the save goes out without its data). Writes in `ao_salvar` take effect; actions requested in it are discarded.
- **Format:** `{"formato": "simant-recomp/estado-dos-mods", "api": "0.26", "tempo": <_GameTime do save>, "mods": {"<nome do mod>": <tabela>}}`. With no mod data at all, the side file is not written and an old one with the same name is deleted (it would belong to another save).
- **Loading:** on Load of an `.ANT`, after `ao_iniciar`, the port reads the side file (if it exists) and calls `ao_carregar(dados, estado)` of each active mod that defines it and has data in it (integers come back as integers). The file is **ignored**, with a line in the log, if it is invalid, of another format, or if `tempo` is not the `.ANT`'s `_GameTime` (for example: the original saved over the save; the data would be from another moment of the game). Data from a mod that is not installed is ignored (and disappears on the next save).
- New game, Tutorial and saves without a side file do not call `ao_carregar`.

### Sandbox and limits

- Libraries: base, `table`, `string`, `math`, `utf8`. **Not available:** `io`, `os`, `package`, `require`, `debug`, `coroutine`, `load`, `loadfile`, `dofile`, `collectgarbage`, `warn`, `string.dump`. Only plain-text source code is loaded (bytecode is refused).
- Limits per call (loading a file or a hook): 1,000,000 VM instructions and 250 ms; total memory of the mod's machine: 16 MiB. `pcall`/`xpcall` do not catch the limit error.
- **Error:** a syntax error, a runtime error, an invalid argument (unknown plane or color, speed outside 0..3...), an exceeded limit, an invalid path or a missing file **turn off that mod's scripts** for the rest of the game. The error goes to the log and the ribbon shows "Mod <nome>: script desligado por erro". The game and the other mods continue.

- **Menu bar:** scripts adding items to the Windows bar (today the mod menu is a separate menu, `definir_menu`).
- **Scripts:** reading the rules' tables (`comum.json` and the parts' tables) through the `estado` object, for scripts that want to check what a data mod changed.
- **Remove acceptance of the old copies of the common tables** (0.20) in a future version, with a warning at least one version ahead.
