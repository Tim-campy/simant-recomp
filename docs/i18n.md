# Languages (i18n frame)

Every text that **the port itself** shows goes through a language frame whose data lives in
`data/idiomas/`, never in the code. The texts of the original SimAnt (menus, dialogs, help,
messages of the game) are not part of it: they keep coming from the user's installation, which is
in English.

Today:

| Context | Languages | What it covers |
|---|---|---|
| `launcher` | `en`, `pt-BR` | the startup options screen (`simant` without options or `--launcher`) |
| `jogo` (game) | `en` | everything after the launcher: messages in boxes and in the message strip generated by the port, refusals of mod actions, mod warnings, window title, console/log messages, `--help` and command line errors, errors of the Lua API |

The infrastructure already allows another language for the game: translate the keys and add
`"jogo"` to that language's contexts in the index. No code change is needed.

## Files

```
data/idiomas/
  idiomas.json      index: languages and the contexts where they can be chosen
  en.json           English (the fallback language; complete)
  pt-BR.json        Brazilian Portuguese (launcher only, for now)
```

### The index: `idiomas.json`

```json
{
  "idiomas": {
    "en":    { "nome": "English",            "contextos": ["launcher", "jogo"] },
    "pt-BR": { "nome": "Português (Brasil)", "contextos": ["launcher"] }
  }
}
```

- The key is the language code (BCP 47 style: `en`, `pt-BR`, `es`, `de-AT`...).
- `nome`: the name shown in the launcher's selector, written in the language itself.
- `contextos`: where the language can be chosen: `launcher` and/or `jogo`.
- The index is an object keyed by code (not a list) so that a mod can add one language by
  merging by key, without repeating the others.
- English is always available, even if it is missing from the index.

### A language file: `<code>.json`

A flat object `"key": "text"`:

```json
{
  "_comentario": "keys starting with _ are comments",
  "launcher.botao.jogar": "Play",
  "mods.script_desligado": "Mod {nome}: script turned off by an error"
}
```

- **Parameters**: `{name}` is replaced by the value the code (or the script) passes under that
  name. A `{name}` without a value stays as it is. `{{` and `}}` are literal braces.
- Keys starting with `_` are comments. Values that are not text are ignored.
- Text is UTF-8. The launcher's 8 × 8 font covers ASCII and Latin-1 (U+00A0–U+00FF: á, ã, ç,
  é, ê, ó, ô, ú, à, ü, ñ...); other characters are drawn as `?`. The game uses the original's
  fonts.

### Key groups

| Prefix | Where |
|---|---|
| `launcher.*` | the launcher screen |
| `cli.*` | command line: errors and `cli.ajuda` (the `--help` text) |
| `programa.*` | program-level messages: fatal error box, log, launcher settings |
| `jogo.*` | in-game texts generated by the port (window title, preferences, sound, saving) |
| `mods.*` | messages about mods: script turned off, refusals of actions (`mods.recusa.*`), dependencies |
| `lua.*` | errors of the Lua API (read by mod authors in the log) |
| `mod.<mod name>.*` | texts of a mod, brought by the mod itself |

## Fallback

When a key is missing in the chosen language, the English text is used and the log gets one
warning per key (`i18n: 'key' missing in pt-BR; using English`). When it is missing in English too,
the key itself is shown (and warned once). English is never missing a port key: a test
(`engine/tests/textos_traduzidos.rs`) checks that every key quoted in the code exists in `en.json`.

## Choosing the language

- **Launcher**: the selector in the title bar. Default: `--idioma CODE` if given, otherwise the
  `idioma` saved in `launcher.json`, otherwise the system language (exact code or the same
  language, so `pt-PT` finds `pt-BR`), otherwise English. Choosing a language saves it in
  `launcher.json` at once.
- **Game**: the same request (`--idioma`, which the launcher puts in the command line, or the
  system language), but only among the languages of the `jogo` context; today that is always
  English.
- System language: on Windows, the user's preferred UI languages (`GetUserPreferredUILanguages`)
  and the user locale; elsewhere `LANGUAGE`, `LC_ALL`, `LC_MESSAGES` and `LANG`.

## Adding a language

1. Copy `data/idiomas/en.json` to `data/idiomas/<code>.json` and translate the values (keep the
   keys and the `{parameters}`). Untranslated keys fall back to English.
2. Add the language to `data/idiomas/idiomas.json` with its name and contexts.

Or as a mod: a mod folder with

```
data/idiomas/idiomas.json   {"idiomas": {"es": {"nome": "Español", "contextos": ["jogo"]}}}
data/idiomas/es.json        {"jogo.erro.load": "Error al cargar: {erro}", ...}
```

Mod language files are merged by key over the port's (like every other `data/*.json`, see
`docs/api-mods.md`), in mod order. They count for the game; the launcher runs before the mods are
chosen and reads only the port's `data/idiomas/`.

## Texts of mods

A mod brings its own keys (`mod.<name>.*`) in `data/idiomas/<code>.json` inside the mod and reads
them in Lua (mod API 0.43):

- `idioma()`: the code of the game's language (`"en"`).
- `traduzir(key, params)`: the text of `key` in the game's language, with the `{name}` parameters
  from the table `params` (values converted with `tostring`). A missing key falls back to English,
  then to the key itself.

The example mods (`exemplos/mods/trapacas`, `exemplos/mods/exemplo-lua`) do this, with English
texts and a Portuguese translation as a second example.

## What is not translated

- The texts of the original game (they come from the user's installation).
- **Developer diagnostics**: errors about corrupt original files, invalid data tables, internal
  invariants and the traces of the automation options (`--ticks`, `--menu`, `--dialogo`...). They
  are written in English directly in the code, for whoever is fixing data or code.
- Data keys and option names (`--sem-som`, `ninho_preto`...): they are identifiers.

A test (`engine/tests/textos_traduzidos.rs`) fails if a string literal in the non-test code of
`engine/src` or `simant/src` looks like Portuguese text.

## Code

- `engine/src/idiomas.rs`: `Textos` (one language with the English fallback), `Indice`,
  `escolher` (the choice rules), the game's global table (`atual`, `instalar`) and the
  `tr!("key", name = value)` macro.
- `simant/src/idioma_sistema.rs`: the system's preferred languages.
- `simant/src/launcher/`: the launcher keeps its own `Textos` and switches it with the selector.
