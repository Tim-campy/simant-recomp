# Main window menu bar (File, Window, View, Options, Speed)

Sources: Ghidra pseudocode (`re_trabalho/decomp/Code1.c`, `Code2.c`, `Code7.c`), `SIMANTW.EXE` resources (`engine/src/formats/ne.rs`), database object 6/0 (`engine/src/formats/menu.rs`, [../formatos/menu.md](../formatos/menu.md)) and QEMU bench captures (640×480, 16 colors) in `re_trabalho/agente_menus/` (outside git), via the scripts `tests/referencias/roteiros/qemu_ui_menus.txt`, `qemu_ui_menus2.txt` and `qemu_ui_menus3.txt` (2026-10-18).

Port: `engine/src/core/barra_menus.rs` (bar, menus, keyboard and mouse), `engine/src/core/status.rs` (Status), `engine/src/core/sobre.rs` (About), `simant/src/menus_ui.rs` (link with the game), `data/barra_menus.json`.

## 1. Where the menu comes from

- The executable **has no MENU resource** (verified: the NE resource table only has cursors, icons, the ACCELERATORTABLE and others; test `aceleradores_do_simantw`). `_InitMenu(0)` (`1008:4e36`), called at initialization (`Code2.c` l. 580), reads **object type 6, id 0** from the database (`_db_LoadObject(0, 6, 0)`) and builds the bar with `CreateMenu`/`CreatePopupMenu`/`AppendMenu`; `SetMenu` puts it on the main window [code].
- Each title becomes a popup; each item, `AppendMenu` with the object's text (`---` becomes a separator, `MF_SEPARATOR` = 0x800). The command number is **`0xFD01 + 16 × menu + item`** (separators also count). An item with a special character and a number would be a submenu loaded from another type 6 object (`_ms_LoadPopUpResource`, ids `0xF9xx`); object 6/0 has none [code; seen in the object dump].
- The accelerators (Ctrl+N etc.) are the executable's ACCELERATORTABLE, with the same numbers (47 entries, read by `ne::aceleradores`).

## 2. Items and what they do (`_ProcMenu`, `1000:4fc2`)

`MAINWNDPROC` receives `WM_COMMAND` with the high byte 0xFD and sends it to `_DoMenuEntry` (`1000:1876`), except the numbers `0xFDAx` (window accelerators, janelas.md §8). `_DoMenuEntry` with help mode on (`_bHelp`) turns the mode off and calls `_ProcMenuHelp`, which opens the item's help (`WinHelp(HELP_CONTEXT, command number)`); otherwise, `_ProcMenu`.

**Checks and texts (`_SetMenuEntries`, `1000:4c24`, also at the end of `_PauseGame`, `_SetPause` and `_ProcMenu`):** a check mark (`CheckMenuItem`, `MF_CHECKED`) on the current speed's item and on each option that is on in `_OptionStates`; the Pause text becomes **"Un&pause\tShift+0"** with the game paused and **"&Pause\tShift+0"** without (`_SetMenuOptionText`, `ModifyMenu`; DGROUP 0x900 and 0x911) [code; bench m05 and n05]. The database object has "&Pause   \tShift+0" (with spaces), which only appears before the first `_SetMenuEntries`.

**Grayed out:** none. The original never calls `EnableMenuItem` (`_CheckItem`, `1000:96b6`, is empty) [code]; in the captures no item appears gray.

**Simulation:** with a menu open, the game does not advance (bench, `qemu_ui_menus3.txt`: `GameTime` 213 → 213 in 4 s with File open) — the Windows menu loop does not let `WM_TIMER` reach the game [hypothesis for the cause; the effect was measured]. The port stops the simulation with the bar active (menu open or title highlighted by Alt [hypothesis for the highlight without a menu]).

## 3. Appearance and navigation (Windows 3.1)

Measured pixel by pixel in captures m00–m11 and n05 (bench, 640×480):

- Bar: screen rows 19–36 (18 rows, white background) and the black row 37; the client area starts at 38 (the same origin as all the other screen specs). Titles in the Windows System font (`VGASYS.FON`), one after the other from x = 0, each one taking the text's width + 8 pixels on each side: File 0–39, Window 40–107, View 108–153, Options 154–219, Speed 220–276. The active title turns blue (the highlight color) with white text, across the bar's full height. The letter after `&` is underlined.
- Drop-down menu: 1-pixel black outline, with the top edge on the bar's black row and the left one at the start of the title's highlight. Outside, a column on the right and a row at the bottom, light gray, offset by 1 pixel (from top + 1 to bottom + 1 and from left + 1 to right + 1) [measured in m01: column x = 144 and row 161 of File; in m05b: x = 167 and row 160 of the system menu; over the ribbon, which has the same color, it is not visible; until 2026-10-19 the port did not draw them]. 18-row items with the font cell at the top; text 16 pixels from the left edge; shortcut left-aligned in a common column, 8 pixels after the widest text; the right edge is 15 pixels after the widest shortcut. 7-row separators with the line (edge to edge) on the 4th. Highlighted item: blue band between the edges, white text. The width is recomputed with the current text (Speed gets wider with "Unpause": right edge at 351 versus 361).
- Check mark: the 8 × 10 pixel drawing in `data/barra_menus.json` (`marca`), 5 pixels from the edge and 3 below the top of the item, in the text color (white on the highlighted item).
- Mouse: pressing on a title opens its menu; with the button held, the highlight follows the cursor across titles and items; releasing on an item chooses it; releasing on the title leaves the menu open with the **first item highlighted** (m09); releasing outside closes it. Clicking outside the bar and the menu closes the menu (the click does not reach the game).
- Keyboard: Alt alone (pressed and released) highlights the File title without opening it (m08); F10 too. With a title highlighted: ←/→ change title, ↓/↑/Enter open it with the first item highlighted, the underlined letter opens its menu, Esc or Alt turn it off. Alt+letter opens directly (m01: Alt+F opens File with About highlighted). With a menu open: ↑/↓ move through the items (skipping separators, wrapping), ←/→ open the neighboring menu, Enter chooses, the underlined letter chooses the item, Esc closes the menu and leaves the title highlighted.

**System menu along the way:** in the original, → on Speed and ← on File pass through the main window's system menu (m05b, s06). In the port this happens with the Windows 3.1 title bar on (`moldura_windows31`, §8); without it (the default), it wraps directly between File and Speed (divergencias.md).

**Check (2026-10-18):** the bar and the five menus drawn by the port (`engine/examples/barra_menus.rs`, and the port's window with `--menu barra@0,0 --capturar-janela`) match **100%** with m00 (closed), m08 (Alt), m01 (File), m02 (Window), m03 (View), m04 (Options), m05 (Speed), n05 (Speed paused, "Unpause") and m11 (Options with AutoTrack checked, except for the mouse cursor: 99.90%). The ribbon of the port's window starts on the right row (99.38% in the region 0–639 × 38–111 of m00, with differences only from the game state). **In 256 colors (SVGA bench 640×480, 2026-10-19, `roteiros/qemu_svga640_256cores.txt`):** File open (About highlighted), File with New highlighted and Speed open (paused) match **100%**, with exact colors, with the example and the `svga256` profile (`--mods` with `{"perfil_driver": "svga256"}`): the highlight is the vbesvga `OEMBIN`'s #a4c8f0 with black text (`tools/comparar_captura6.py`, telas/resolucao.md §7).

## 4. Quit (`_MenuQuit`, `1000:d628`)

- Called by File → Quit (Ctrl+Q), by the main window's `SC_CLOSE` (closing the window, Alt+F4) and by `WM_QUERYENDSESSION` [code, `MAINWNDPROC`].
- **Always** asks (does not look at `_gGameNeedsSaving`): `MessageBox("Do you want to save the current ant hill?", "SimAnt Quit", 0x1123)` — Yes/No/Cancel, question icon, **No** as default (`MB_DEFBUTTON2`) [code; bench m19]. Yes → `_SaveGame(0)` (Save As): saved, the game ends; cancelled, it continues. No → ends (bench o03: Windows is left without SimAnt). Cancel → back to the game (m20). A second call after an answer does not ask again (`DAT_1048_164e`).
- Port: the same box as the Load question (dialogos.rs, `pergunta_sair`) with the title "SimAnt Quit": **99.51%** of the m19 box (the differences are the icon, the port's own drawing, and the cursor). Closing the port's window and Esc (a port extension: before, it quit immediately) also open the question; with the question open, closing the window again quits.

## 5. About (`_AboutDialog`, `1000:cf3a`)

- Stores `_GamePaused`, calls `_SetPause(1)` ("Game Paused" on the ribbon), opens window 31 (`aboutWin`: background `aboutPic1` = bitmap 3000 with the title "ABOUT SIMANT" and the copyright, and the picture `aboutPic2` = bitmap 3001) and captures the mouse.
- Loop: waits with the picture; then erases the picture (redraws `aboutPic1`) and scrolls the credits from **list 4/1700** with font 4, each line centered on the width of `aboutPic2` and clipped to it, **one pixel up per step**, starting with line 0 at the top; when the last line leaves, the picture comes back and the cycle restarts [code].
- Closes with a click or Space/Insert (`_win_Events`): in the first steps the event is discarded (`local_e` > 1 with the picture, > 3 while scrolling); a click with the picture before that only starts the scrolling [code]. Esc does not close it. On closing, `_SetPause(the previous one)` (bench: m16 stayed paused because the game was paused before; n13 unpaused).
- Timings [measured on the bench; the wait argument of `_WaitedEnough` does not appear in the pseudocode]: picture for ~7.5–8.6 s (n11 still with the picture at ~6 s; n12 at offset 0 at ~7.6 s; m14 at 25 at ~12.7 s) and ~172 ms per pixel (131 pixels in 22.5 s between m14 and m15). The port uses 8 s and 165 ms (3 periods of 55 ms) [hypothesis].
- Frame: the Windows dialog frame (black outline, 4 blue lines and the rest of the border) [measured in n09].
- **Check:** with the picture, **98.81%** of n09 (the original's frame is 1 pixel to the right of the port's, with the content in place [cause unknown]); the scrolling finds the right offset with 95.9–97.6% of the pixels of the credits area (n12, m14, m15; text against background).

## 6. Status (`_ScoreDialog`, `1000:5caa`; Window → Status, Ctrl+T)

- **It belongs to the game, it is not for debugging:** item "&Status\tCtrl+T" of the Window menu, window 24 with the title "STATUS" (bitmap 13000), columns COLONY and UNIVERSE and the overall score (bench n02).
- `_CalcScore` gives the 8 grades (mensagens.md, "Score"; `avisos::parciais`). Grades 0–3 go to the text objects `antEffEH`, `antEffFC`, `antEffAH`, `antEffFW` (Colony Health, Foraging, Eggs Hatched, Fights Won), with their format ("%d%%"). `_win_DrawScoreWindow` (`1000:5aca`) writes with font 4: in the Full Game (`_CurGameType` 2), grades 4–7 ("%d%%") in `antEffCS`, `antEFFCH`, `antEffYF`, `antEffHF` (Colonies Started, Colonies Held, Yard Filled, House Filled); in the others, "N.A." (4/1800[16]); below, 4/1800[13] + game type name (4/1001) + 4/1800[14] ("Overall Quick Game Score") and the score ("%ld"); in Experimental, 4/1800[17] and [18] in place of those two lines. The footer (`antEffContStr`, "%s") gets 4/1010[14], "Click here to continue" [code; texts checked in n02].
- Closes with a click, Space or Insert (`_win_Events`) or Esc (`_DialogAbort`) (bench: m18, n03, o02). **The simulation keeps running** with the window open (`_win_Events` dispatches `WM_TIMER`; bench: `GameTime` 119 → 139 in 5 s with Status open). The port redraws the grades every frame.
- **Check:** with the capture's grades (97, 0, 100, 100; 19806), **100%** of the n02 window, with the window 3 pixels to the left of the computed position (`ajuste`) and the texts one row above the end-of-game rule [measured; cause unknown]. **Full Game and Experimental (bench, 2026-10-19, `roteiros/qemu_status_full.txt` and `qemu_status_exp.txt`, captures and states in `re_trabalho/ag8/status/`):** Ctrl+T on the `full` and `exp` snapshots; the port with the state read at the same stop (`--save …_estado.ANT --dialogo status`, `comparar_captura.py --mapear`) gives **99.56%** and **99.62%** of the window: grades 4–7 in "%d%%" in the Full Game (50%, 100%, 0%, 0%) and "N.A." in Experimental, "Overall Full Game Score" and "Score not available / in Experimental Game" in the right places; only the cursor, the right-border column and, in the Full Game, the score digits differ (27587 in the original, 27598 in the port with the state from 2 s after the window opened) [hypothesis: the original computes the score on opening and does not redraw it; the port redraws every frame]. ## 7. Load Game from "Select a Game"

`_NewGame(0)` with Load Game does the same as File → Load (`_LoadGame`); with no game (at the opening, `_CurGameType` = −1), if the Load fails or is cancelled, `_DoMenuEntry` calls `_NewGame(0)` again [code]. Port: during a game, File → Load (with the question, if the game changed); at the opening, "Load Ant Hill" over the opening background (Cancel goes back to "Select a Game"; the chosen file opens like `--save`). **Bench (2026-10-19, `roteiros/qemu_load_abertura.txt`, captures `re_trabalho/raros/load/a1`–`a5`):** the click on Load Game (345, 375) **closes** "Select a Game" before opening "Load Ant Hill", which sits in the same place as the in-game File → Load, over the empty background; QUICK2 loads paused ("Game Paused", `_GamePaused` = 1), title QUICK2.ANT, nest view. The port drew the dialog on top of "Select a Game" and now removes window 2 (`simant/src/main.rs`). The loaded screen matches `--save QUICK2.ANT` at 99.94% of the edit window (the cursor); outside it, the map window behind differs (divergencias.md, 2026-10-19). **Cancel (2026-10-19, `roteiros/qemu_load_abertura_cancelar.txt`, captures `re_trabalho/ag8/load_cancel/c1`–`c5`):** Esc in "Load Ant Hill" closes the dialog and "Select a Game" reappears **identical** to before (only the cursor differs: 220 pixels, in 6 bits) already 1 s later; a click on Quick Game right after starts the game (`_CurGameType` = 1). That is what the port does (`LoadNaAbertura`: Cancel goes back to the choice).

## 8. Title bar and system menu of the main window

**The original** (`_InitInstance`, `1000:3c8a`: `ShowWindow(..., nCmdShow | 3)`, `SW_SHOWMAXIMIZED` [code]) runs **maximized with the title bar visible**: the frame is off-screen and what remains is the title (rows 0–17 and the black row 18) and the menu bar (19–36 and row 37); the client area starts at row 38, the screen minus 38 rows [measured in m00 and in all bench captures; resolucao.md §1]. SimAnt does not touch the main window's system menu (`_win_Open` only changes the child windows', janelas.md §8), so it is the Windows 3.1 default [code + capture].

**Measured** on the VGA bench (640 × 480, 16 colors), captures m00 and m05b (`re_trabalho/agente_menus/`) and s00–s16 (`re_trabalho/moldura/`, script `tests/referencias/roteiros/qemu_ui_moldura_principal.txt`, 2026-10-19):

- **Title** (18 rows): system menu box at x 0–17 (light gray, with the black and white 13 × 3 dash on rows 7–9 starting at x = 2 and the dark gray shadow at x = 15 and on row 10), black line at x = 18; the blue band (`COLOR_ACTIVECAPTION`) from 19 to 601 with "SimAnt" in the System font, white, centered on the band (`DT_CENTER`; the "S" starts at x = 289); black line at 602; minimize button 603–620 (down arrow of 7, 5, 3 and 1 pixels on rows 7–10, centered on the button's column 8), black line at 621 and the restore button 622–639 (the window is maximized: up arrows on rows 4–7 and down on 10–13). Raised buttons: 1 white pixel at the top and left, 2 dark gray at the bottom and right.
- **Inactive** (with the Quit question, s12, or the Windows Task List, s14, in front): white band and black text; box and buttons the same.
- **Pressed button** (s08, s10): only the dark gray line at the top and left, no relief, and the glyph 1 pixel to the right and 2 down. Dragged outside with the button held, it returns to normal and releasing there does nothing (s09, s11).
- **System menu**: a click on the box (s01), Alt+Space (s03) or ← on File/→ on Speed followed by ↓ (s07, m05b) open the menu below the box, with the top outline on the title's black row (y = 18) and the left one at x = 0, with **Restore highlighted**; the box is **inverted** (the VGA complementary color) while the menu is open or the box is chosen by keyboard (s02, s05, s06: Esc with the menu open leaves the box inverted, like a bar title). Items: Restore, Move, Size, Minimize, Maximize, —, Close Alt+F4, —, Switch To... Ctrl+Esc; **Move, Size and Maximize grayed out** (light gray). Geometry the same as the bar's menus (§3): 167 pixels wide (the shortcut in the column 8 pixels after "Switch To...", the edge 15 after "Ctrl+Esc"), 18-row items, 7-row separators, the light gray column and row outside. The highlight also goes through the grayed-out items (↓ on Restore highlights Move, s04), and a highlighted grayed-out item has the `GrayString` text: only the pixels with even x + y, in white (s04). Choosing a grayed-out item does nothing.
- **Commands** (`MAINWNDPROC`, `WM_SYSCOMMAND` on `_mainRootWnd`, `1000:2930`) [code]: `SC_CLOSE` (Close, Alt+F4, double-click on the box) kills the timer and calls `_MenuQuit`: the same "SimAnt Quit" question as File → Quit (s12; Esc cancels, s13); `SC_MINIMIZE` releases the mouse capture and goes to `DefWindowProc`; the others, to `DefWindowProc`. Minimized, SimAnt becomes the icon on the desktop (s16).
- **Pace without focus** (`gt_a`–`gt_g`): `GameTime` advanced 61 ticks in 10 s with the window active, with the Task List in front and minimized (regras/simulacao-visao-geral.md §1).

**In the port** (video option `moldura_windows31` in `data/video.json`, or `--moldura`/`--sem-moldura`; **default `true` since 2026-10-19**, before `false`; non-interactive runs go without it unless `--moldura` is explicit; decisoes.md 2026-10-19): with it, the port's window gains the title's 19 rows above the menu bar (640 × 480 at scale 1, the bench's whole screen) and:
