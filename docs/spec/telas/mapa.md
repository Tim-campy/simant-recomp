# Map window (`mapWin`, window 1)

Overview of the current plane: surface, black nest, red nest or one of the five pheromone maps, with the ants, the spider, the boy's footprint and the edit view rectangle. Source: Ghidra pseudocode (analysis of 2026-10-18; addresses below), the instruction listing of `_OpenMiniMapWin` and `_MapAreaEvent` (Ghidra script over a copy of the project, working material outside git) and the WINGANT/SHARED layouts. **Captures of the original** (bench, 2026-10-18; sections 6 and 7): nest, the five pheromones, clicks and Shift+clicks in the area, swap with the yard and the mini map; trails still without a capture.

## 1. Window

- Layout 1 (`mapWin`, object 0 = outline t = 2), position from the type 9 table (entry 1: (118, 24), 516 × 278) + the ribbon, like the control windows (janelas.md). Visible objects: `mapTitle` (0x101, 18-line title) and `mapTileArea` (0x102, 513 × 256: 512 × 256 plus the extra pixel of `_win_GetObjRect`). The other objects (scent buttons, plane buttons, window buttons, Mystery, population panel) are hidden: with the ribbon, the controls are on it [layout; hypothesis that they only appear without the ribbon].
- `_InitMapFunctions` (`1010:c19c`): 4 × 4 pixels per cell (`_mapXsize` = `_mapYsize` = 4) [code].
- Opening: Window → Map/Yard (Ctrl+M, `_ProcMenu` 0x12 → `_OpenMapYard` `1000:9b2a`): if the map or the yard is already open, it comes to the front; otherwise `_YardToMap` (`1000:972a`): `_SetMapPlane(1)` and the map on the surface. The map and the yard occupy the same place (`_win_Swap(0x100, 0x1900)`); `_MapToYard` (`1000:9918`) goes back to the yard [code].
- **`_win_Swap(de, para)`** (`1030:d434`) [code]: only acts if `de` is open; hands to `para` the `HWND` of `de` (which is left without a window), the window rectangle and the corner of object 0, redoes the measurements (`_win_Recalc`), marks `para` as open, writes the `HWND`'s `INDEX` property with the number of `para`, `SHOWWINDOW` and invalidates everything. Since the `HWND` is the same, the place in the window order does not change either. **Bench** (`bancada_mapa.py mapa1`, p06–p08): the map dragged by the title 50 pixels to the left and 34 down; `ribToYard` put the "Yard View" exactly in the moved map's rectangle (and not at the yard's original position, (62, 18) from table 9/0), and `ribPatch` returned the "Surface View" to the same place. In the port: `Gerenciador::trocar` (same place in the stack and same rectangle); test `troca_com_o_quintal_no_lugar_do_mapa_movido` (`simant/src/mini_ui.rs`).
- **Title** (`_SetMapTitle`, `1000:953c`): the `_MapMode` entry of the SHARED list 4/1000: 0 "BackYard View", 1 "Surface View", 2 "Black Nest View", 3 "Red Nest View", 4 "Black Nest Marker Pheromone", 5 "Black Trail Marker Pheromone", 6 "Red Nest Marker Pheromone", 7 "Red Trail Marker Pheromone", 8 "Alarm Signal Pheromone" [code + data].

## 2. Mode (`_SetMapModeAnt`, `1000:9e82`; `_MapMode` = `8:8610`)

- n from 4 to 8 with `_MapMode` = n: goes back to 1 (the same scent button again turns the pheromone off).
- n from 4 to 8: if `_MapPlane` ≠ 1, first `_SetMapPlane(1)` — pheromones only exist on the surface.
- Writes `_MapMode`, changes the title and marks the mode's button on the ribbon (group 1 of window 34; n ≤ 3 unmarks the group).
- `_SetMapPlane` ends with `_SetMapModeAnt(_MapPlane)`: **changing plane goes back to that plane's plain map** [code].
- Buttons of ribbon 34 (`_ProcMapRibbonEvent`, `1010:c3d4`): `ribBNestScent` → 4, `ribBTrailScent` → 5, `ribAlarmScent` → 8, `ribRNestScent` → 6, `ribRTrailScent` → 7; when on they also write `_ELayerMode` (1, 2, 0, 3, 4; off, −1) and redraw the edit window: the scent button changes the map and the edit window's overlay layer at the same time [code].

## 3. Drawing

`_DrawMap` (`1010:cd3e`) generates the map buffer (unnamed routine `1010:d7a0`) and `_DrawMapData` (`1010:cb60`) only updates the ribbon panel (populations and health). Painting (`_win_DrawMapWindow`, `1010:ce46`) only copies the buffer [code].

Generation: one color byte per cell in a 128 × 64 buffer, compared row by row with the previous generation's (`_lastMapMapBuf`) to invalidate only what changed; each byte becomes a 4 × 4 pixel block [code]:

- **Surface** (`_GenOverMap`, `1018:46e9`): life ≠ 0 → `_LTab[life >> 3]` (the ant on top); otherwise `_CTab[terrain]` (yard) or `_HTab[terrain]` (house).
- **Nests** (`_GenNestMap`, `1018:4754`), 64 × 64 in the middle (128-pixel offset, side strips of `_ConvColor(0xF)`): life 0 → `_CTabR[terrain >> 2]` (also in the black nest: `_CTabB` is not used); 0xFE/0xFF (yellow ant) → `_ConvColor(1)`; < 0x80 (black) → `_ConvColor(0xF)`; others → `_ConvColor(3)`.
- **Pheromone** (modes 4 to 8: `_PherMapBN`, `BT`, `RN`, `RT`, `A`): each cell of the 64 × 32 grid covers 2 × 2 cells; value 0 → `_ConvColor(0xB)`, v > 0 → color 16 + (v >> 4), a ramp of dithered 4 × 4 blocks (tables `1048:1a56`, `1a96`, `1ad6`, `1b16`). Does not draw ants.
- The DGROUP tables are in the Mac numbering and are converted once by `_PatchColorArrays` (`1000:3f0c`) with M = [F, B, 2, 9, E, 5, 4, C, 2, A, 7, 3, 6, 8, 7, 0]; the converted values are in `data/mapa.json`. The `_ConvColor` table (`1008:4c0e`) is filled at run time [hypothesis: the same M].
- **On top** (plane 1, without trails): the spider (`_SpidOn`), bitmap 1100 + `_SpidDir` at (4·(`_SpidX` >> 4), 4·(`_SpidY` >> 4)) (`_DrawMapSpider`, `1010:d10e`); the footprint (`_FootHere`), bitmap 1200 + (`_BoyDir` & 3) at (4·`_FootX`, 4·`_FootY`) and, with `_BoyHere` 3 or 4, the lawnmower 1210 + (~`_BoyDir` & 1) at (4·`_MowX`, 4·`_MowY`) (`_DrawMapFoot`, `1010:d226`).
- **Cursor** (`_DrawMapCursor`, `1010:c652`): the edit view, a 2-pixel XOR rectangle at (4·`_MapPnt.x` + offset, 4·`_MapPnt.y`) with 4·`_editWidth` × 4·`_editHeight`.
- **Trails** (`_showTrails`, DGROUP `1998`; configurable button 4 and object 0x10E): **not pheromone**. When on and with the same mode, generation starts from the cells of the previous generation and only writes those that have life: the ants' old positions stay painted and accumulate tracks (without spider or footprint). When turning it on with the spider present, the original first redraws without it, so as not to leave the sprite's track [code].
- **When:** in `_UpdateWindows` after each tick (with the speed as in the edit window). With the map open: in front (or at ultra, `_GameSpeed` = 3) `_DrawMap` (generates and shows) and the alternation (`DGROUP:0x72f0`) goes back to 0; behind, `_DrawMap` and `_DrawMapData` (only generates the buffer, without putting it on screen) take turns, starting with `_DrawMapData`; with the map closed, `_DrawMapData`. `_GotoMyAnt` (with the yellow ant on the plane shown), `_GotoMapPoint`, `_GotoSpider`, `_GotoQueen` and `_GotoBQueen` reset the alternation [code, `1000:2224`]. Visible consequence: behind another window, the visible part of the map changes every other tick; with AutoTrack and the yellow ant walking (one `_GotoMyAnt` per tick), almost never. **No map drawing routine does a random draw** [code]: the alternation does not change S nor the state. **Port (2026-10-19):** generation continues every tick (trails accumulate the same way), and the screen shows `JanelaMapa::na_tela`, copied only when the tick did `_DrawMap` (`Partida::tomar_mapa_na_tela`, alternation reset by `ir_para_amarela` and by the markers); generation outside the tick (plane change, opening) appears immediately. Not checked against a capture.

## 4. Interaction (`_MapAreaEvent`, `1010:e100`)

Only for a point inside `mapTileArea` [code]:

- **Without Shift** (`GETASYNCKEYSTATE(VK_SHIFT)`): loop while the button is held. At each new mouse position, cell = ((x − area.left) / 4, (y − area.top) / 4), minus 32 columns when the map shown is 64 wide (nests); inside the plane, it erases the rectangle, `_CenterEdit` on the cell (the edit view goes there; the edit window is redrawn mid-drag only with AutoTrack, `_OptionStates[0]`; without it, on release) and draws the rectangle again. In the nest's side strips, nothing.
- **Double-click** (bits 0x60 of byte 7 of the event, as in the yard): after centering, `_OpenEditWindow` (`_win_Open(0)`): the edit window comes to the front. The first click of the pair already centered once; since `_CenterEdit` moves in a straight line and the minor axis can stop one step short, the second completes it [code; bench p03: from (18, 30) to cell (90, 20), view at (78, 11) and the edit window in front].
- **With Shift**: no loop and no centering. The cell (x / 4, minus 32 only if `_MapPlane` is 2 or 3, and then only from 0 to 63) becomes the corresponding edit window point ((cx − `_MapPnt.x`) × `_tileWidth` + corner, likewise in y) and goes to `_processEdit` with the same event, which converts it back into the same cell, even outside the view. Since the edit window is not the front one, there is no ~6 `_TickCount` wait of the simple click; and with Shift held there is no yellow ant menu nor Examine. Result: in Experimental, the tool (`_processExp`); on the yellow ant, `_CenterAnt`; otherwise the go order (`_MeGoal*`, `_MeMoveMe` = 1) and, with a double-click, the act order (`_MeCmd` = 1) [code `1000:6a38`]. **Bench** (`bancada_mapa.py mapa2`/`mapa1`): Shift+click on surface cell (60, 30) gave `_MeGoalX/Y` = (60, 30), `_MeGoalPlane` = 1, `_MeMoveMe` = 1 and the view did not change (q01); in the black nest, on the side strip (map column 10), nothing (q03); on column 52, the order to (20, 30) of the nest (q04); Shift+double-click at (70, 35): `_MeCmd` = 1 (p05). In a first attempt (p01) the Shift reached Windows after the button and the click only centered.
- The mini map (window 20, `ribToYellow` on the ribbon) is another window, modal, without pheromone: section 7.

| Mode | Equal |
|---|---|
| 2, black nest | **99.89%** |
| 4, Black Nest Marker | 96.28% |
| 5, Black Trail Marker | 98.48% |
| 6, Red Nest Marker | 93.78% |
| 7, Red Trail Marker | 99.52% |

**Finding:** with the game paused the scent button changes the title and the mode, but the map content is **not** regenerated (the surface's remains, from `_SetMapPlane(1)`): generation only happens in `_UpdateWindows`, after a tick. That is why the pheromone captures were taken after a tick (Shift+0, one tick, Shift+0). **Fixed (2026-10-18):** the port also only regenerates after a tick (`JanelaMapa::atualizar` looks at `_GameTime`); without a tick, only opening and plane change regenerate, with the plane's plain map. To export a pheromone with the game paused, use `--ticks 1` (like the bench). The remaining differences in the pheromones (up to ~6% in 6) are in the blocks of the dithered ramp (colors 16+ converted by `--mapear`); they were not isolated. Another port finding: `--janela-mapa N` with `_MapMode` already = N in the save toggles and turns off the pheromone (like the original's button); `comparar_capturas.py` starts from `_MapMode` = 1. **Fixed:** `--janela-mapa N` does not press the button when the save is already in mode N.

Same bench, scripts from `tools/bancada_mapa.py` (`rico` snapshot on a copy of the overlay; captures outside git): `mapa1`/`mapa2` (clicks, Shift+clicks, double-click, drag, swap with the yard; sections 1 and 4) and `mini1`/`mini2`/`mini3` (section 7).

## 7. Mini map (`miniMapWin`, window 20; `_OpenMiniMapWin`, `1010:e374`)

**It exists and is used on Windows**: the `ribToYellow` button of ribbon 34 (object 6, (207, 41)–(232, 59), the first of the second row; `_ProcMapRibbonEvent` 0x2206) opens it [code; bench m01]. The object's name is a leftover: the button does not go to the yellow ant.

Layout: object 0 `miniMapWin` (outline, (20, 20)–(152, 88), 132 × 68) and `miniMapArea` ((22, 22)–(150, 86), 128 × 64).

Opening [code]:

1. Stores `_GamePaused`; scale = 1 pixel per cell in color (`_displayType` 10; 2 in monochrome).
2. `_win_Open(0x1400, x, 0)` with x = button's left + (button's width)/2 − (object 0's width)/2 (153 for `ribToYellow`), captures the mouse and draws (`_Mini_DrawMapI`, `1010:d474`) the `_MapPlane` plane: surface (`FUN_1010_c854`: `_GenOverMap` with `_CTab`/`_HTab` and `_LTab`, like the map window; **never pheromone**, even with `_MapMode` 4–8) or nest (`FUN_1010_ca66`: `_GenNestMap` of the red nest if `_MapMode` = 3, otherwise of the black one, 64 wide, with 32-pixel `_ConvColor(0xF)` strips on the sides); no spider and no footprint. With trails and `_MapMode` equal to that of the last generation (`_lastMapGenMode`), it starts from the map window's buffer (`_lastMapMapBuf`) and only writes the cells with life; with a different mode, it calls `_win_MapChanged` and writes `_lastMapGenMode`.
3. The view rectangle: 1-pixel XOR outline at (area.left + scale × `_MapPnt.x` + 32 in the nests, area.top + scale × `_MapPnt.y`), with `_editWidth` × `_editHeight` (`_mmapCursorState` = 1).
4. If the mouse button is still held (the ribbon event comes on press), it waits for release: **released inside the mini map area**, it closes and calls `_OpenMapYard` (the map or the yard comes to the front; bench m15: pressing the button, moving the mouse inside and releasing brought up the "Surface View"); released outside, the mini map stays open.
5. `_SetPause(1)` and the modal loop (`_win_GetEvent`, which dispatches the Windows messages): button pressed **inside the area** = drag loop, with `_CenterEdit` on the cell ((x − area.left) / scale, minus 32 with 64 columns; (y − area.top) / scale) at each new position, as in the map window (`_UpdateEdit` mid-drag with AutoTrack, otherwise on release); **outside the client area** = closes; inside the client area and outside the map area, the code calls `_CenterEdit` with the coordinates in pixels (probable oversight), but the map area covers the whole client area, so this does not happen.
6. On closing: releases the capture, discards pending events (`_win_FlushEvents`) and goes back to the previous pause (`_SetPause(stored)`; the ribbon shows "Game Paused" while the mini map is open).

**Bench** (2026-10-18, `bancada_mapa.py mini1`, `mini2`, `mini3`):

The port: `ajuste_x` = 3 (the place of the following openings, still measured) and `alinhamento_ao_criar` = 8 (`MiniMapa::abrir`).

## 8. Edit window scent layer (`_ELayerMode`) and the `_EditScentMenu` menu

Who writes `_ELayerMode` [code; all references in the pseudocode]: the scent buttons of ribbon 34 (section 2: 1, 2, 0, 3, 4; off, −1, without touching `_MeDropAlarm`); `_SetAlarmDropState` (`1000:84cc`: 0 when turning on the yellow ant's alarm on the surface, −1 when turning it off; called with `_MeDropAlarm` ≠ 0 by `_DoAntMoveY`, `_EnterNest` and `_LessonDone`, case 0x1e); key 0 and the yellow ant's command 7 (`_YellowCommandKey`, `_YellowCommand`); `_YellowDeath` and `_InitYelloAnt` (−1 with the alarm on); and `_EditScentMenu` (`1010:675e`). Only `_DoCalcTile` and the balloons (`_DrawCurBalloons`, telas/baloes.md) read it. All the writers are in the port (`Estado::camada_edicao`; telas/jogo.md, "Camada de cheiro na janela de edição"), except the menu.

**`_EditScentMenu` is unreachable on Windows** [code + layout]: it opens the proximity menu of window 6 (`editScentMenu`: Off, Alarm, BNest, BTrail, RNest, RTrail; highlighted item = `_ELayerMode` + 1) next to object 0x10 of the edit window (`editScent`) and, once an item is chosen, writes `_ELayerMode` = item − 1, marks `editScent` as selected if ≠ −1 and redraws the edit window; only `_ProcEditEvent` calls it, on the event of object 0x10. But `editScent` has flags 0x0800 in the layout (neither visible, bit 0x01, nor clickable, bit 0x02: `_win_FindObject` and `_win_GetEvent` only find objects with 0x02), like the whole icon column (`editIcons`, 0x0200), and no game code makes them visible or clickable (`_win_MakeObjSelectable` is only called for 0x401, 0x1902 and 0x1E01). The "selected" state of `editScent`, also written by `_SetAlarmDropState` and by key 0, therefore never appears. With the ribbon, the scent buttons of ribbon 34 play that role. The port has neither the menu nor the button state (no visible effect; recorded in divergencias.md).

## 9. Ribbon panel (`_DrawMapData`, `1010:cb60`)

Complete in the port: besides the numbers and bars (mensagens.md §9, checked on the bench), the routine only has the two inverted threshold columns (`_BlkWarnHealth` on the black health bar, `_MeWarnHealth` on the yellow ant's), also reproduced (`core/barras_faixa.rs`), and it only draws with ribbon 34 open [code]. It is called at the end of `_DrawMap` and by `_UpdateWindows`; it draws nothing inside the map window.
