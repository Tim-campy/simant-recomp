# Yard window (Yard View), patch transfer and Full Game

This document describes the yard window (window 25, opened by the code as `0x1900`), the yard ribbon (window 35, `ribbonYard`), choosing and transferring patches (`_XferPatch`), placing queens (`_PlaceQueenInYard`) and the Full Game flow (start, goal and end). The yard rules that run in the tick (boy, animals, colonies, victory and defeat) are in [../regras/quintal.md](../regras/quintal.md); the generation of the new patch, in [../regras/geracao-mundo.md](../regras/geracao-mundo.md).

Implementation: `engine/src/core/quintal_mapa.rs` (window geometry, drawing and clicks, no SDL), `engine/src/rules/troca_patch.rs` (`_XferPatch` and `_PlaceQueenInYard` over the `Estado`), data in `data/quintal_mapa.json` (partly generated by `tools/extrair_quintal_mapa.py`), executable in `simant/src/modos.rs`.

**Sources and legend:** **[code]** = Ghidra pseudocode in `re_trabalho/decomp/` (reference only), with the `selector:offset` address and the name from `SIMANTW.SYM`; **[data]** = bytes of `SIMANTW.EXE` or of the banks; **[measured]** = measured pixel by pixel in a capture from the QEMU bench (640×480, [../../bancada-qemu.md](../../bancada-qemu.md)); **[hypothesis]**; **[open]**.

Reference captures (QEMU bench, 2026-10-17, scripts in `re_trabalho/modos/`, outside git): `full_inicio.png` (Full Game right after being chosen), `full_yard.png` (Yard button), `yard_strat.png`, `yard_graphic.png`, `yard_house.png`, and `yard_strat2.png`/`yard_graphic2.png` (with colonies written into memory: `_YMapPopB`/`_YMapPopR` via `escrever_variavel`).

## 1. Yard coordinates

The yard has **12 × 16 patches**, `(px, py)` with `px` 0–11 and `py` 0–15; index into the `_YMapPopB/R` maps = `px × 16 + py` [code]. Patches with index ≤ 37 (`px` = 0 or 1, or `px` = 2 with `py` ≤ 5) are the **house** (`_MakeMap`, geracao-mundo.md §3); the others, the lawn. Each patch is a parallelogram: one step in `px` moves 28 pixels to the right; one step in `py` moves 10 pixels down and 10 to the left [code: `_InvertPatch` `1010:be04`, `_DrawSimColonies` `1010:bea4`, `_YardArea` `1010:c09a`].

With `(ox, oy)` = corner of `_mapTileRect` (`9:8110`), vertex `k` of the patch is

```
x = ox + 28·px − 10·py + polígono[k].x        y = oy + 10·py + polígono[k].y
```

with two polygons from DGROUP [data]:

| Table | Address | Vertices (x, y) | Use |
|---|---|---|---|
| `_patchRgn` | `1048:1894` | (169, 67), (192, 67), (185, 74), (162, 74) | cursor (`_InvertPatch`) and click |
| `_patchRgn2` | `1048:18a4` | (169, 67), (193, 67), (186, 74), (162, 74) | colony color (`_DrawSimColonies`) |

In modes 0 and 1 the cursor is 1 pixel to the left (`−1` in the x of `_InvertPatch`) [code].

**Click → patch** (`_YardArea`, same computation in `_PlaceQueenInYard`): `py = (y − oy − 67) / 10` and `px = (10·py + x − ox − 169) / 28`, C integer division (truncates toward zero); valid if 0 ≤ `px` < 12 and 0 ≤ `py` < 16 [code]. Because of the truncation, the row just above patch (0, 0) also falls into `py` = 0 [code; not tested on the original].

`(ox, oy)` on the bench = corner of the client area of window 25: the cursor of patch (11, 8) appears with its top-left corner at (517, 304) on screen, which gives `(ox, oy)` = (120, 157) = corner of the client area [measured in `yard_strat.png`].

### 2.5 Mode 3: bars (`_DrawColonyBars` `1010:bf9c`)

For each patch with population *p* ≠ 0, a bar `(p + 3) >> 2` pixels high, with its base at `oy + 10·py + 71` and its left edge at `ox + 28·px − 10·py + 168` (black, 9 wide, color `_ConvColor(15)` = black) or `+ 180` (red, 9 wide, `_ConvColor(3)` = red) [code; colors measured in `yard_graphic2.png`]. The fill is `_GRectFill` [hypothesis: half-open rectangle, right and bottom exclusive].

### 2.6 Current patch cursor (`_DrawYardCursor`/`_InvertPatch`)

The current patch (`_CurYardPnt`, `9:7a60`) is marked with `_patchRgn` [code]. On screen [measured]: in modes 0 and 1, only the outline of the polygon in magenta (index 13); in modes 2 and 3, the polygon filled with light gray (index 8) with a dark gray outline (index 7). The original achieves this by inverting the pixels (`_TrapFill` without colors, inversion mode) [hypothesis]; the port draws the measured colors (`data/quintal_mapa.json`, `cursor`).

**The cursor disappears after a patch transfer (bench 2026-10-19, `re_trabalho/agyard/c_xfer`, x2–x4):** after the double click that transfers patches with box 10006 on screen, the original no longer shows the patch cursor (neither on the old nor on the new one) while the yard stays open. `_DrawYardCursor`/`_EraseYardCursor` invert the pixels and keep a flag (`DGROUP:18b6`); the window redraw after the box closes only paints the part covered by the box (clipping), so the inversion on the new patch falls outside the clip, but the flag stays on [code + capture; explanation = hypothesis]. The port draws the cursor on the new patch (not reproduced: effect of XOR with clipping; divergencias.md).

## 5. Choosing a patch, transferring patches and placing queens

### 5.1 Click (`_YardArea`)

Left click in the yard area (object `0x1902`): computes the patch (section 1) and, if it is inside the yard, writes `_YMapPnt` = (px, py) (the chosen patch). If the click is a **double** click (bits 0x60 of the event) it calls `_XferPatch` [code].

### 5.2 `_XferPatch` (`1000:ab90`)

With `t = (tx, ty) = _YMapPnt` and `i = tx × 16 + ty` [code]:

1. If `t = _CurYardPnt`: nothing.

   - if `_YMapPopR[i] = 0`: `_HealthR = 0`;
   - `_ClearBookmarks`;

### 5.3 `_PlaceQueenInYard` (`1000:ad12`)

`PLACE` button (`0x2307`) [code]:

1. If `_QueenStorageB < 1`: error sound and message in the ribbon (list 1010: 7 "You have no new queens to drop" in the Full Game, 16 "Place queens in Full Game only" in the others; duration 0xB4); end.
2. `_LayDownQueenMode = 0` (if it was 1); the valid patches are those up to 3 away in x and in y from the current patch (limited to the yard).
3. Stops the simulation (`_StopSimulation`); on each loop iteration, the permanent message 1010[8] "Click in yard to place new queen"; the player moves the mouse (the patch under the mouse is inverted if it is valid and different from the current one) and clicks in the yard area. If the yard stops being the front window, clears the ribbon and exits.
4. Outside the valid range: 1010[10] "That location is out of bounds" (0x78) and error sound (with Shift, `_myDelay(30)`). Inside: music `0x2AFB`, `_QueenStorageB −= 1`, `_YMapPopB[patch] += 1`, `_BColoniesStarted += 1`, `_ColonyUpdateFlag = 1`, map redraw and 1010[9] "You have started a new colony" (0x78); with no more queens, it ends. After any click, the loop continues **while Shift is held down** (`GetAsyncKeyState(VK_SHIFT)`); otherwise it ends.
5. Resumes the simulation.

Note: the current patch is also accepted (there is no different-from-current test in the confirmation) [code].

**In the port** (2026-10-18): the PLACE button calls `troca_patch::iniciar_colocacao` (messages and `_LayDownQueenMode`) and turns on "place queen" mode, with the simulation stopped (`Partida::parada_pela_interface`); each click in the yard area calls `colocar_rainha` (same test, same changes and messages) and `continuar_colocacao` decides based on the Shift state at the time of the click; closing the yard ends the mode and clears the ribbon. ## 6. Full Game: start, goal and end

Summary of what the code does (details in the rules specs) [code]:

- **Start** (`_NewGame` type 2, geracao-mundo.md §1–2): patch (11, 8), no black colony, the yellow ant is a **winged queen** (T = 0x40) on the surface, `_MeNestStarted = 0`, `_MapPlane = 1` (surface). The ribbon shows "You need to dig a nest" [measured in `full_inicio.png`]. The red colony starts on the same patch. **There is no yard window nor goal box at the start** (bench 2026-10-19, `re_trabalho/agyard/a_inicio`, 12 captures from 1 to 23 s after choosing Full Game in snapshot `sel2`): the edit window on the surface with the winged queen in the center, the surface map behind, `_MapPlane` = 1, `_YardMode` = 0, and the only message is the ribbon's. In the code, `_NewGame` only calls `_MapToYard` with `_MapPlane` = 0, and `_RandYard` sets 1 in the Full Game; `_DoScenario` shows no text [code]. The port does the same. The goal of the Full Game is only stated by the manual and the help.
- **Middle**: the queen digs the nest (`_MeNestStarted` = 1); the colony grows; winged queens take off (`ribMate`) and go to `_QueenStorageB`; the player places them on other patches (`PLACE`, section 5.3); every 32 ticks `_SimColonies` makes the yard colonies grow and fight (quintal.md §10). The player can **change patch** with a double click on a patch with a black colony (section 5.2).
- **Goal / victory**: when there are more than 24 colonies (black or red) in the house area (`_HouseColonies > 24`), the house is put up for sale (`_ForSaleState = 1`, message 10054); if after that there is no red colony, game over with victory (`_IsGameOver = 1`, `_BlackWon = 1`, message 10057).
- **Defeat**: fewer than two black colonies in the yard and no black queen, egg, larva or pupa (`_CastePopB[5,0,3,4] = 0`): `_IsGameOver = 1`, `_BlackWon = 0`, message 10056.
- The game-over dialog (`_EndGameDialog`, window 4 `gameOverWin`) is requested through the event queue (`Evento::DialogoFimDeJogo`); its drawing belongs to other work (messages/dialogs).
- **Victory sequence** [code, `1030:3215`…]: music 0x4e25, box 10057 ("Congratulations! By defeating the red ants and invading the house you have won the Full Game.", third parameter 1: appears even with Events turned off), `_DrawSimPayoff` (Yard View in front and window 26 with the rolling eyes; **no text**: only bitmaps and music) and, afterwards, the game-over dialog with the score. The `fred` cheat (`_ProcCheat` 0x14) calls only `_DrawSimPayoff`: animation without any message, in the original too. The eyes (2/16210–16212) are `kind` 0 bitmaps (opaque) with magenta corners (index 13) and `_win_DrawBitMap` copies them without a mask (with `kind` 3 it would draw nothing): the magenta outline of the eyes **is from the original** (bench `re_trabalho/cen/payoff/pay_010.png`). Port: test `vitoria_mostra_o_texto_antes_da_animacao`.
