# World generation (new game and yard patches)

This document describes how the original builds the world of a Tutorial, Quick Game, Full Game or Experimental game, and how it generates each yard patch. The random generators are in [rng.md](rng.md): **S** is the LFSR (`_SRand*`) and **R** is C's `rand()` (`_RRand`). The map values are in [tiles-valores.md](tiles-valores.md).

Conventions:

- Addresses `selector:offset` with the name from the `.SYM`. Variables: `_Name` (segment `1038` = seg. 8, `1040` = seg. 9, `1048` = DGROUP). Many variables appear in Ghidra's pseudocode only as an offset (e.g.: `*(int*)0x80b4`) because the code swaps `ES` with selectors stored in DGROUP; the name was resolved from the offset in segments 8/9/10 and from context, and checked in the disassembly when there was doubt.
- Coordinates: `_MapA` has 128 × 64 cells, index `x * 64 + y`; `_MapB`/`_MapR` have 64 × 64, index `x * 64 + y`, with `y = 0` on the surface row. `x` is horizontal and `y` vertical (fact: the shape tables of the rocks, of the hole border and of the antlion only form coherent drawings, with corners and edges in place, in that orientation; see [tiles-valores.md](tiles-valores.md)).
- Directions 0–7 by the tables `_Dx8` (`1038:0000`) = `0, 1, 1, 1, 0, −1, −1, −1` and `_Dy8` (`1038:0008`) = `−1, −1, 0, 1, 1, 1, 0, −1`: 0 = up, 2 = right, 4 = down, 6 = left (fact verified: bytes of segment 8 in the executable).
- `_SRand1(n)` is written `S(n)`; `_SRandK()` is written `Sk(K)`; `_SGRand(n)` is `SG(n)`.

## Verification done

**Fact verified (2026-10-16)** against `tests/referencias/saves/QUICK2.ANT` (Quick Game saved by the original on the QEMU bench): reimplementing in Python the sequence described here from the seed saved in `_YMapSeeds`, the result reproduces:

- `_MapB` and `_MapR`: **identical** (4,096 of 4,096 bytes each, including the random tunnel values and the edge smoothing);
- `_MapA`: identical except for 10 cells, all of critters that moved during the game (pill bugs, 0x70–0x73, and a caterpillar, 0x69–0x6B, which appears later);
- `_HoleMapB[32] = 3` and `_HoleMapR[32] = 118`; red queen at (41, 11) with T = 0xE2 and the half at (40, 11) with T = 0xEA, equal to the saved R list;
- `_FoodA = 117` (the save has 117).

Script: `re_trabalho/verifica_geracao_quick2.py` (working material, outside git). The port reproduces the same result in Rust, with more variables checked (see "Implementation in the port"). The generation of the **house** (`_MakeHousePatch`) was verified later, on four patches generated by the original's `_XferPatch` (§5.3), and, on 2026-10-19, on thirteen patches covering all the recipes in the table of §5, plus two yard patches with several colonies (§5.3). The new games of **Full Game, Experimental and Tutorial** were checked on the same day with the whole state (307 blocks) before the first tick, and the new game **chosen during a match** in all four types (§8).

## 1. Choosing the game: `_NewGame` and `_DoScenario`

`_DoScenario` (`1000:5998`) opens window 2 (`scenarioWin`, id 0x200) and returns the id of the clicked object. The names come from object type 1 no. 2 of the `SHARED` bank (fact verified: `re_trabalho/dump2/SHARED/t01_00002_b1.bin`). `_NewGame` (`1000:d6dc`) converts the id into the game type `_CurGameType` (`1040:80b4`). Fact seen in the code.

| Id | Object | `_DoScenario` returns when | `_NewGame` does |
|---|---|---|---|
| 0x202 | `scenQuickGame` | click | `_CurGameType = 1` |
| 0x203 | `scenFullGame` | click **or Enter key** (`GetAsyncKeyState(0x0D)`) | `_CurGameType = 2` |
| 0x204 | `scenExperimental` | click | `_CurGameType = 3` |
| 0x205 | `scenCancel` | click or `_DialogAbort` | returns −1 without changing anything |
| 0x206 | `scenTutorial` | click | `_CurGameType = 0` |
| 0x207 | `scenLoad` | click | `_LoadGame(0, 0)`; if it fails, shows the dialog again |

For types 0–3, `_NewGame`, in this order: ends pending tool modes (`_CurGameTool` 10 or 11), if a pair of DGROUP variables (`0xcf22/0xcf24`, unnamed) is not zero, swaps the bitmaps of a ribbon button (one pair of bitmaps for Experimental, which also clears `_CurExpTool`, and another for the other types), `_SetDefaultWindPrompt(1)`, `_SetEditWinTitle`, `_QueenStorageB = 0`, `_JustXfered = 1`, `_LayDownQueenMode = 1`, `_UpdateLayQueenModeDisplay`, **`_RandYard()`**, and, only in the Tutorial (type 0), `_TutLesson = 1`, `_TutGiven = 0` and opens window 0 (`editWin`) if the parameter is 0. Then it reopens the caste/mode, map and edit windows and centers the view on the yellow ant. Fact seen in the code.

Notes (facts seen in the code):

- The **Tutorial from the menu** is a type 0 game generated by normal `_RandYard`. The routine `_GenerateTutorial` (below) only runs when a file named `Tutorial.Ant` is loaded (string 1800 of the bank, object type 4 no. 1800 of `SHARED`), via `_LoadGame` or `_SpecialTutorialInit` (`1010:9cea`).
- `_InitSimVars` (`1030:5a70`) is **not** called on a new game, only at program initialization (`_initStuff`) and in the file tutorial. It sets `_GameSpeed = 1`, `_MeWarnHealth = 30`, `_BlkWarnHealth = 30`, `_CurExpTool = 0`, `_SwarmCntR = _SwarmCntB = 0`, `_QueenStorageR = _QueenStorageB = 0`.
- The new game does **not** reseed S or R: the world depends on the state of R at the moment of the click (see step 2.4).

## 2. `_RandYard` (`1030:6086`)

Order of actions (fact seen in the code):

1. `_ClrArrays` (`1030:6dec`): clears `_MapA`, `_LifeA`, `_MapB`, `_MapR`, `_ExitMapB`, `_ExitMapR`, `_LifeB`, `_LifeR`, the six pheromone maps (`_PherMapA`, `_PherMapF`, `_PherMapBN/BT/RN/RT`) and the ant lists.
2. `_ClearHistory(1)`, `_initControls()`.
3. `_CurYardPnt = _YMapPnt = (11, 8)`; `_InitSimYard` (`1030:1378`: boy at (0xB4, 0x49), dog at (0xFA, 0x96), clears cat, bird, rain etc.).
4. Clears match states: `_CurGameTool = −1`, `_LastThemeTime`, `_TimeTemp`, `_LastThemeSong`, `_HouseColonies`, `_JustToBeMean`, `_BlackWon`, `_IsGameOver`, `_ForSaleState`, `_Invincible`, `_NeverHungry`, `_AlwaysHealthy`, `_GameTime` (32 bits).
5. `_MapPlane = 2` (black nest) if `_CurGameType < 2`, otherwise `1` (surface); `_MapMode = _MapPlane`; `_YardMode = 0`.
6. **Patch seeds:** for each of the 192 words of `_YMapSeeds` (`1038:0224`), in increasing address order: `seed = (RRand(0x7FFF) + 0x4000) & 0x7FFF`. Values from 0 to 0x7FFE.
7. `_MeNestStarted = 1` if `_CurGameType ≠ 2`, otherwise `0`.
8. `_RandWorld(seed, blacks, reds = 1, x = 11, y = 8)`, with `seed = _YMapSeeds[8 * 12 + 11]` and `blacks = 1` if `_CurGameType ≠ 2`, otherwise `0`.
9. Copies `(_MeLocX, _MeLocY)` to the view pointer of the yellow ant's plane: `_AMapPnt` (plane 0/1), `_BMapPnt` (2) or `_RMapPnt` (3).

Summary by game type (fact seen in the code, direct consequence of the steps above and of `_RandWorld`):

| Type | `_CurGameType` | Initial view | Black colony | Yellow ant | Initial food | Spider |
|---|---|---|---|---|---|---|
| Tutorial (menu) | 0 | black nest | yes | worker (T = 0x10) in the black nest | yes | **off** (`_SpidOn = 0`) |
| Quick Game | 1 | black nest | yes | worker in the black nest | yes | on |
| Full Game | 2 | surface | **no** (neither hole nor queen) | winged queen (T = 0x40) on the surface | yes | on |
| Experimental | 3 | surface | yes | worker on the surface at (0x40, 0x20), `_MeMode = 2` | **no** | on |

## 3. `_RandWorld(seed, blacks, reds, px, py)` (`1030:5ab0`)

Callers: `_RandYard` (new game and before loading a save) and `_XferPatch` (`1000:ab90`, patch change in the Full Game, with `blacks = _YMapPopB[px][py]` and `reds = _YMapPopR[px][py]`). Exact order (fact seen in the code; steps 3.1 to 3.12 verified in `QUICK2.ANT`):

1. `_SetSRandSeed(seed)`.
2. `_InitSpider` (`1020:4668`): no random draw. Spider at `_SpidX = 0x400`, `_SpidY = 0x200` (coordinates ×16), direction 0, `_SpidBurpCnt = 10`, `_SpidOn = (_CurGameType ≠ 0)`, no target.
3. `_MakeMap(px, py)` (`1020:3100`): `n = px * 16 + py`; if `n > 0x25` (37), `_MakeYardPatch()`; otherwise `_MakeHousePatch(n)`. The initial patch (11, 8) gives 184, yard.
4. `blacks += blacks >> 2` and `reds += reds >> 2` (×1.25 with truncation; 1 stays 1).
5. For all 4,096 nest cells: `_MapB = _MapR = 0x2E` (solid dirt), `_ExitMapB = _ExitMapR = 0`, `_LifeB = _LifeR = 0`; and the 8,192 of `_LifeA = 0`. **Caution:** this happens after `_MakeMap`, so, in `_XferPatch`, the patch generation (antlions, step 4.3) still sees the `_LifeA` of the previous patch (only `_RandYard` clears it before).
6. Surface row of the nests, for each column `c = 0…63`, in order: if `_TERRAINset = 0` (yard), `_MapB[c][0] = 0x1C + Sk(4)` and then `_MapR[c][0] = 0x1C + Sk(4)`; in the house, if `py > 3`, both receive `0x1C + S(2)` (in that order), otherwise both receive `0x1E` without a random draw. `_ExitMapB[c][0] = _ExitMapR[c][0] = 0xFF`.
7. Clears the six pheromone maps.
8. **Black ants on the surface** (`_LifeA`): `k = S(6)`, `j = Sk(2)` (always drawn, even with `blacks = 0`). Repeats `blacks` times: `x = SG(128)` (pulled to the left), `y = Sk(64)`; if `_MapA[x][y] < 0x50`: if the `_LifeA` cell is free, draws `v = Sk(16)` and the type T:
   - `v < k + 7` → `0x10 + Sk(8)` (worker [name hypothesis, see save-ant.md]);
   - otherwise, `v < 15 − j` → `0x30 + Sk(8)`;
   - otherwise, `Sk(2) = 0` → `0x40 + Sk(8)`, otherwise `0x20 + Sk(8)`.
   The 3 low bits are the direction. If the cell already has an ant, the attempt does not count (up to 49 repetitions in total per colony). If `_MapA ≥ 0x50`, the attempt is lost without repetition.
9. **Red ants on the surface:** the same, with `reds`, `x = 127 − SG(128)` (pulled to the right) and the types with bit 7 set (0x90, 0xB0, 0xC0, 0xA0 + direction).
10. Clears `_HoleMapB` and `_HoleMapR`. If `_CurGameType ≠ 2` or `blacks > 0`: `_MakeNewHoleB(32)`. If `reds > 0`: `_MakeNewHoleR(32)` (see 3.A).
11. Clears the digging accumulators (`_TileTotXB/YB/XR/YR`, `_TilesDugB/R`, `_TileMassXB/YB/XR/YR`) and sets `_WaterTable = 64` (no flooded row).
12. If `blacks > 1`: `_DigOutBNest(blacks * 16)`; if `reds > 1`: `_DigOutRNest(reds * 16)` (see 3.B). In a new game this never happens (values 0 or 1).
13. `_BuildAntListA` (rebuilds list A by scanning `_LifeA`, x from 0 to 127 and y from 0 to 63, M = 2, S = 0), `_ClearListB`, `_ClearListR`, `_BlkQueens = _RedQueens = 0`, `_LastBlackEgg = _LastRedEgg = (−1, −1)`.
14. If `reds > 0`: red queen (same logic as `_PlaceRedQueen`, written inline; see 3.C).
15. If `blacks > 0`: `_PlaceBlackQueen()` (3.C).
16. `_InitYelloAnt()` (3.D).
17. `_FoodB = _FoodR = _FoodA = 0`; if `_CurGameType ≠ 3`: `_AddFood(−1, 0)` (3.E).
18. `_HealthB = _HealthR = 100`, `_EditMsgDelay = 0`, `_BlackLost = _RedLost = 0`, `_Cycle = 0`, `_ClearHistory(0)`, `_CountAnts()`, invalidates the screen map, `_MapPnt = _AMapPnt = (0x40, 0x20)`, `_BMapPnt = _RMapPnt = (0x20, 1)`.

### 3.A Entrance holes: `_MakeNewHoleB(c)` (`1020:1b06`) and `_MakeNewHoleR(c)` (`1020:1d02`)

The parameter `c` is the nest column; on the surface the hole is on row `y = c` (fact seen in the code: `_MapA[x * 64 + c]`).

In the yard (`_TERRAINset = 0`):

1. `r = S(31)`.
2. For `t = 0…33`: black: `x = (r + t) mod 32 + 2` (x from 2 to 33, left side); red: `x = 126 − (r + t) mod 32` (95 to 126, right side). Stops at the first `x` for which `_IsClear3x3(1, x, c)` is true (see [tiles-valores.md](tiles-valores.md): cell and 8 neighbors inside the map, without an ant and with ground `< 0x10`). If none fits, it exits without doing anything.
3. `_MapA[x][c] = 0x50` (hole); each neighbor `d` (0–7) that is inside the map and has a value `< 0x50` receives the border `DGROUP:0x230c[d]` = `19 1a 1c 1f 1e 1d 1b 18`.
4. `_LastNewHoleB/R = x`, `_LastNewExitB/R = c`, `_HoleMapB/R[c] = x`.
5. Black: `_DigTileB(c, 1)`. Red: digs `_MapR[c][1]` (if it is dirt, `Sk(8)` and accumulates the digging) and smooths the four neighbors and row 0, like `_DigTileR`.

In the house (`_TERRAINset ≠ 0`), the loop does not test `_IsClear3x3`: it accepts the first cell whose value has a "with hole" version (`_CanBeHouseHole`, `1020:1cba`: 0 → 0x86; 2 or 3 → 0x8A; 0x5E–0x61 → value + 0x22; 0x66 → 0x85; 0x68 → 0x84) and does not draw a border. Verified against the original (§5.3): `_MakeNewHoleB` in the twelve house patches checked and `_MakeNewHoleR` in the six of them with a red colony.

### 3.B Digging a nest: `_DigOutBNest(n)` (`1030:62de`) and `_DigOutRNest(n)` (`1030:63b8`)

Fact seen in the code; not exercised in the new game.

```
pos = (32, 1); dir = 4 (downwards); dig (32, 1)
repeat n times:
    dir = (dir + S(5) − 3) & 7          // turn from −3 to +1: the drift is asymmetric
    nx = x + Dx8[dir]; ny = y + Dy8[dir]
    if nx < 1:  nx = 1,  dir = 2   else if nx > 62: nx = 62, dir = 6
    if ny < 2:  ny = 1,  dir = 4   else if ny > 62: ny = 62, dir = 0
    if _DigTileThemB(nx, ny) dug:
        pos = (nx, ny)
        if ny == 1 and _HoleMapB[nx] == 0: _MakeNewHoleB(nx)
```

`_DigTileThemB(x, y)` (`1020:22d4`) only digs if `0 < x < 63`, if the cell below is dirt (or `y > 62`) and if the one above is dirt (or `y < 3`); it does not require the cell itself to be dirt (an already dug cell is drawn again). At `y = 0` it writes 0x18 and opens a hole; otherwise it writes `Sk(8)`. Then it accumulates the digging, smooths the four neighbors and updates `_ExitMapB`.

### 3.C Queens: `_PlaceBlackQueen` (`1030:65ce`) and the red queen

Red queen (inline in `_RandWorld`; `_PlaceRedQueen`, `1030:67da`, has the same logic but has no callers in the pseudocode):

```
x = 32; depth = Sk(4) + 7
for y = 1 to depth − 1:
    dig (x, y)
    t = x + S(3) − 1                     // −1, 0 or +1
    if 7 < t < 57: x = t
dig (x, y); x += 1; y += 1               // two diagonal steps, down and to the right
dig (x, y); x += 1; y += 1
dig (x, y)                               // queen's chamber
_LastRedEgg = (x, y)
rx = x + 2
dig (rx, y), (rx − 1, y), (rx − 2, y)
list R: (rx, y) with T = 0xE2 (queen facing right), M = 9, S = 0
list R: (rx − 1, y) with T = 0xEA (second half), M = 9, S = 0
_RedQueens += 1
```

The black queen is the same, with `_DigTileB`, list B, T = 0x62 and 0x6A, `_BlkQueens += 1`, and with two differences: the lateral drift is only drawn again when `Sk(2) = 0` (otherwise it repeats the previous one, starting at 0); and it also writes the chamber position to `_RebornX/_RebornY` (`1040:9fec/9fee`), where the yellow ant is born. Order of random draws in the black queen per row: dig, `Sk(2)`, and only if it gives 0, `S(3)`.

"Dig" is `_DigTileB/R(x, y)` (`1020:1fe4`/`21de`): if the cell is dirt (0x20–0x2E), it becomes tunnel with value `Sk(8)` and adds (x, y) to the center-of-mass accumulators; then it smooths the four neighbors (`_SmoothEdges`, see [tiles-valores.md](tiles-valores.md)) and updates the exit map of the dug cell (`_FixExitMapB/R`, `1020:284e`/`2914`: on rows 0 and 1, 0xFF if the cell is a 0x18 opening and 0xFE if not; below, the largest `_ExitMap` of the 8 neighbors minus 1, or 0 if all are 0; the neighbors are not recalculated). `_ExitMap` therefore grows like a distance to the surface, but only in the order in which the cells are dug. Fact seen in the code; verified in `QUICK2.ANT` (`_ExitMapR` identical, `_ExitMapB` equal except for one cell changed by the simulation, see "Implementation in the port"). In `_DigTileB`, if `y > 53` and `S(64) = 0`, the cell becomes 0x14 in **both** nests [hypothesis: passage between the nests].

### 3.D Yellow ant: `_InitYelloAnt` (`1030:6492`)

`_MeBase = 0`, `_MeEggCarried = 0xFD`, health 100. Fact seen in the code:

- Experimental: plane 1 (surface), `_MeMode = 2`, position (0x40, 0x20), `_MeType = 0x10`. No random draw.
- Full Game without a nest (`_MeNestStarted = 0`): up to 100 attempts of `x = 0x20 + Sk(16) − Sk(16)`, `y = 0x20 + Sk(8) − Sk(8)` (in that draw order), until finding `_MapA < 0x10`; if none fits, it uses (0x40, 0x20). It places a winged queen (`_MeType = 0x40`) on plane 1, direction 2.
- Other cases: worker (`_MeType = 0x10`) on plane 2 (black nest) at `(_RebornX, _RebornY)`, direction 2.

The yellow ant marks `_LifeA/B` with 0xFF instead of entering the lists (`_SetMyLife`, `1020:6536`); only when the type is 0x60 (queen) does it also occupy the cell behind (opposite direction) with 0xFE. The worker and the winged queen of the new game occupy one cell. In Experimental, `_InitYelloAnt` does not call `_SetMyLife`: no `_LifeA` cell is marked. If the nest cell is dirt or closed surface, `_SetLife` digs it (`_DigMyTile`, not specified); during generation this does not happen, because the ant is born in the queen's chamber. Fact seen in the code.

### 3.E Initial food: `_AddFood(−1, 0)` (`1030:6a58`)

```
cx = 0x40; cy = S(48) + 8; amount = 200          // with parameter ≥ 0: cx = Sk(128), cy = Sk(64)
_LastFoodDrop = (cx, cy)
radius = Sk(8) + 5
repeat amount times:
    a = Sk(256); r = S(radius)
    x = cx + trunc(cos(a) * r / 0x7FFF); y = cy + trunc(sin(a) * r / 0x7FFF)
    if (x, y) is on the map and without an ant in _LifeA:
        yard:  ground < 0x18 → 0x48; 0x48–0x4A → +1; counts _FoodA
        house: ground < 4 → (ground + 6) * 4; ground 4–0x17 → ((ground − 8) & ~3) + 0x18; 0x18–0x27 with (value & 3) < 3 → +1; counts _FoodA
```

`sin`/`cos` use the 64-word table of object type 9 no. 1000 of the bank (`_FracSineTab`, `1040:9fca`, big-endian words, `sin(i·π/128)·32767`): angle from 0 to 255 for one full turn, value 0x7FFF at angle 64, negative sign from 128 to 255; `cos(a) = sin(a + 64)`. The division is signed and truncates toward zero. Fact seen in the code; verified in `QUICK2.ANT` (center (64, 38), 117 units).

## 4. Yard patch: `_MakeYardPatch` (`1020:41a2`)

Fact seen in the code and verified in `QUICK2.ANT` (all cells, except critters that moved):

1. If `_TERRAINset ≠ 0`: `_CurGndTileID = 1000` and `_OverlayTileSet(0, 1000)` (loads the yard tiles, object type 9 no. 10, `_TERRAINset = 0`, `_Barrier = 0x50`).
2. **Ground:** for the 8,192 cells in index order (x from 0 to 127, and within each x, y from 0 to 63): `_MapA = Sk(16)`.
3. **Rocks:** `_AddRocks` (4.1).
4. **Antlions:** `_InitAntLions(Sk(4) + 1)` (4.2).
5. **Pill bugs:** `_InitPillar` (4.3).
6. **Objects** (position `x = S(125) + 1`, `y = S(61) + 1`, drawn in that order; only written if all the cells involved are `< 0x18`; no new attempt):
   - 20 times, 2 × 2 block: (x, y) = 0x20, (x+1, y) = 0x21, (x, y+1) = 0x22, (x+1, y+1) = 0x23;
   - 30 times, horizontal pair: `v = (S(2) + 0x12) * 2` (0x24 or 0x26; the `S(2)` is only drawn if both cells fit), (x, y) = v, (x+1, y) = v + 1;
   - 100 times, cell 0x28;
   - 128 times, cell 0x51 (pebble that can be carried).

### 4.1 `_AddRocks` (`1020:4334`), `_AddRock5` (`1020:44ec`), `_AddRock3` (`1020:45ac`)

```
n = S(3) + 2                                    // 2 to 4
repeat n times:    for shape k = 0…5:  y = S(58); x = S(122); _AddRock5(x, y, k)
repeat 2n times:   for shape k = 0…5:  y = S(60); x = S(124); _AddRock3(x, y, k)
```

The draw order is **y before x** (fact verified in the disassembly: the second argument is computed and pushed first). ### 4.2 `_InitAntLions(n)` (`1030:40c6`)

Fact seen in the code: `_LionIndex = 0`, `n = min(n, 10)`, `_InitialLions = n`. For each antlion, up to 200 attempts: `x = S(64) + S(65)`, `y = S(32) + S(33)` (triangular distribution around the center); it accepts if `_IsClear3x3(1, x, y)`, or, after 100 attempts, if only the central cell is free. It writes 0x38 in the center and, in each free neighbor (`_IsClearTile`), `0x30 + DGROUP:0x25e8[d]` with the table `1 2 4 7 6 5 3 0` (that is, 0x30 top-left corner, 0x31 top, 0x32 top-right corner, 0x33 left, 0x34 right, 0x35 bottom-left corner, 0x36 bottom, 0x37 bottom-right corner).
