# Saved game (`.ANT`)

The `.ANT` has no header. It is the concatenation, in fixed order, of 307 blocks of the game's memory, totaling **48,386 bytes**, written raw in little-endian (x86 memory).

**Source:**
- Fact seen in the code: `_SaveGame` (`1010:a23e`) walks the table in data segment 8 (`SIMANT_DATA_GROUP`, selector `1038`), offset `0x9570`, and for each entry `{u16 count, u16 element size, far pointer}` writes `count × size` bytes with `_lwrite`. The table ends at the first entry with `count = 0`. `_LoadGame` (`1010:9fa0`) reads it back with the same table.
- Before writing, `_SaveGame` checks the free disk space and requires 125% of the sum of the blocks.
- The table below was generated by `tools/save_table.py`, which resolves the segments by following the NE relocation chains. The names come from `SIMANTW.SYM`.
- **Verified (2026-10-16):** `QUICK2.ANT`, saved by the original on the QEMU bench (`docs/bancada-qemu.md`), is exactly 48,386 bytes (`tests/referencias/saves/QUICK2.ANT`).

This table is also the **simulation state model**: everything that must survive saving and loading is here. Prefix legend (inferred from the names): `A` = surface (the current patch), `B` = black nest, `R` = red nest, `Me` = yellow ant (the one controlled by the player), `YMap` = map of the whole yard (*yard*, see below), `H_` = historical series of the graph.

The dimensions and indexing of the main arrays are in the [Main structures](#main-structures) section, below the table.

**Port data:** the same table is in `data/save_layout.json` (symbol without the leading `_`, `count`, `tamanho`, `endereco`), generated with `python tools/save_table.py SIMANTW.EXE SIMANTW.SYM --json data/save_layout.json`. The loader (`engine/src/formats/save.rs`) reads the layout from that file, not from the code. The test `layout_bate_com_a_tabela_do_executavel` (`engine/tests/save_ant.rs`) checks `count` and `tamanho` against the executable when `SIMANT_DIR` points to it.

## Main structures

Sources: Ghidra pseudocode in `re_trabalho/decomp/` (outside git), functions named from `SIMANTW.SYM`, and `QUICK2.ANT`. Legend: **[code]** = seen in the pseudocode, with the function's address; **[save]** = observed in the data of `QUICK2.ANT`; **[hypothesis]** = inference not yet confirmed.

Coordinate convention: `x` is the column (horizontal) and `y` the row (vertical; in the nests, the depth). All the large maps are stored **column by column**: the byte for `(x, y)` is at `x * height + y`.

### Terrain maps

| Block | Dimension | Index | Evidence |
|---|---|---|---|
| `_MapA` (surface) | 128 × 64 | `x * 0x40 + y`, `x & 0x7f` | [code] `_DoCalcTile` (`1018:4a6b`), `_DoWater` (`1020:07c6`), `_ExitHole` (`1020:2db6`) |
| `_MapB` (black nest) | 64 × 64 | `x * 0x40 + y`, `x & 0x3f` | [code] `_DoCalcTile`; `_DoWater` walks `x = 0..63` on row `y = _WaterTable` with step `0x40` |
| `_MapR` (red nest) | 64 × 64 | same as `_MapB` | [code] same |
| `_ExitMapB`, `_ExitMapR` | 64 × 64 | same as `_MapB` [hypothesis] | [save] 255 along the whole row `y = 0` and values 254, 253, … going down the tunnel: looks like a distance field to the exit [hypothesis] |
| `_HoleMapB`, `_HoleMapR` | 64 | per nest column `x` [hypothesis] | [save] single non-zero value at `x = 32`, the column of the tunnel entrance |

- `_DoCalcTile` chooses the map by the plane `_MapPlane`: 0 and 1 use `_MapA`, 2 uses `_MapB`, 3 uses `_MapR` [code]. In the nests, the ground tile drawn is `value − 0x70` (byte, with overflow) [code].
- On the surface, the value is the ground tile itself [code]. `_DoWater` draws grass at random with `_SRand1(0xe)` (0 to 13) and treats 0x74–0x77 as puddles that grow with the rain [code]; `_ExitHole` only accepts exiting onto cells `< 0x50` [code]. In `QUICK2.ANT` the values range from 0 to 114 [save].
- Nest flooding (`_DoWater`): when `_WaterTable` rises, row `y = _WaterTable` becomes `'N'` (0x4E) if the value was `< 0x20`, or `value + 0x2F` otherwise; when drying, it does the reverse (`'N'` becomes `_SRand1(8)`) [code]. With `_WaterTable = 64` (no flooded row) the nests of `QUICK2.ANT` have values from 0 to 0x2E, and 0x2E (solid earth [hypothesis]) fills ~97.5% of the cells [save].
- Confirmation of the column-major order with data: the ants in lists B and R are on cells other than 0x2E (dug tunnel), the tunnel goes down diagonally from `(32, 0)` to `(36, 9)` and row `y = 0` is entirely different from 0x2E [save; test `formigas_dos_ninhos_estao_em_tuneis_coluna_major`].

### Pheromone maps

`_PherMapA`, `_PherMapBN`, `_PherMapBT`, `_PherMapRN`, `_PherMapRT`: 2048 bytes each, **64 × 32**, one cell for each 2 × 2 block of surface tiles, index `(x >> 1) * 0x20 + (y >> 1)` [code: `_DoCalcTile`, which chooses the map by `_ELayerMode` 0 to 4 in that order and draws `(value >> 4) − 0x10` when `value > 0x10`]. All five use surface coordinates in that function; whether `BN`/`BT`/`RN`/`RT` also apply inside the nests has not been seen [hypothesis: surface only].

### Life maps (not saved)

`_LifeA` (128 × 64), `_LifeB` and `_LifeR` (64 × 64) store, per cell, the T field of the ant that is there (0 = empty; 0xFF and 0xFE = yellow ant) [code: `_DoCalcTile`, `_AddAntToAList`]. **They are not in the save**: `_DoLoadInitializations` (`1010:9dbe`) clears all three and rebuilds them from the lists, walking each one from `_ListIndex?` down to 0 inclusive (the lowest-index entry wins when two occupy the same cell), and then calls `_SetMyLife` for the yellow ant if `_MeMode == 0` and `_FullCount` [code]. Full rules in [telas/jogo.md](../telas/jogo.md#life-layer).

### Ant lists

Each area has five parallel byte vectors, one element per ant: `X`, `Y`, `M`, `T`, `S`. Capacity: 1000 in `A`, 500 in `B` and `R` [code: limits in `_AddAntToAList` (`1020:2ef0`), `_AddAntToBList` (`1020:2f4a`), `_AddAntToRList` (`1020:2fa4`)].

- **The list belongs to the area, not the colony.** `A` = ants on the surface; `B` = inside the black nest; `R` = inside the red nest. Each ant's colony is in bit 7 of `T`. `_DoNestAntB` (`1028:2dae`) handles red ants (`T & 0x80`) inside list B, which invade the black nest [code]; in `QUICK2.ANT` list A has one black worker (T = 17) and one red (T = 150) [save].
- **Counters:** `_ListIndexA`, `_ListIndexB`, `_ListIndexR` (saved) = number of used entries, `0..ListIndex` [code]. `_AddAntTo?List` writes at position `ListIndex` and increments. An entry with `T = 0` is a hole (dead/removed ant): `_CompactListA/B/R` (`1020:2a16`/`2a7a`/`2ade`) shifts the following entries and decrements the counter; `_DoAntSim` (`1028:0000`) calls one compaction every 32 cycles, alternating A, B, R [code]. `_RemoveFromAList` (`1020:2b42`) removes by shifting (`_BlockMove`) and clears the cell in `_LifeA` [code]. `_BuildAntListA` (`1020:3046`) rebuilds list A by scanning `_LifeA` (x from 0 to 127, y from 0 to 63) [code].
- **X, Y:** cell coordinates in the area's map (A: x 0–127, y 0–63; B/R: 0–63) [code: `_AddAntTo?List` also writes `T` into `_Life?[x * 0x40 + y]`].
- **T (type)** [code: `_CountAnts` (`1020:04de`), `_GetFromAlist` (`1020:2ffe`), `_DrownBList` (`1020:2d16`), `_DoCalcTile`]:
  - bit 7: red (1) or black (0) colony;
  - bits 3–6: class `k` (0–15). `_CountAnts` counts `T >> 3` (32 counters, black 0–15 and red 16–31);
  - bits 0–2: for types `< 8` (class 0), the drawing uses `_MeEgg` instead of `_MeDir`, so class 0 = brood and the low bits indicate the stage [hypothesis]; in adults, direction 0–7 [hypothesis, supported by `_lifeTile = T + 0x100` (surface) or `T + 0x200` (nest), where T would be the sprite index].
  - `_CountAnts` groups the classes into `_CastePopB/R[6]`: `[0] = k0`, `[1] = k1+k2+k3+k5`, `[2] = k6+k7+k9`, `[3] = k4`, `[4] = k8`, `[5] = k12`, and sets `_BpopT/_RpopT = sum of [1..5]` (without the brood) [code]. If `[5]` goes from non-zero to zero, it plays music and shows the end-of-colony dialog, and in the quick game (`_CurGameType < 2`) sets `_IsGameOver` and defines `_BlackWon` [code], so `k12` = queen.
  - Names of the other classes [hypothesis, to be confirmed through the bitmaps/sprites]: group `[1]` workers, `[2]` soldiers, `[3]`/`[4]` breeders (winged males/females). `k13` always appears next to the queen (T = 110 at x = 35 with the queen T = 102 at x = 34; in the red colony 234 next to 226) and is not counted in any group: probably the second half of the queen's sprite [hypothesis]. `k14` (`T = 0x70 | color`) is written as the result of a fight in `_DoNestAntB` (corpse? [hypothesis]).
  - `_DrownBList`/`_DrownRList` drown (M = 0x11) the ants on row `y = _WaterTable` with class 1–11, that is, neither brood nor queen [code].
- **M (mode/task):** index from 0 to 19 of the per-mode counters (`20` words per colony, cleared every cycle in `_DoAntSim` and summed into `_ModePopB/R[6]`: `[0] = m2+m3`, `[1] = m4+m5`, `[2] = m1`, `[3] = m7`, `[4] = m12`, `[5] = m6`) [code: `_DoNestAntB`, `_DoAntSim`/`_TallyModePop` (`1028:038e`)]. Values seen: 2 when rebuilding list A [code: `_BuildAntListA`]; 7 = raid nest (`_RaidInB`) [code]; 10 after winning a fight [code]; 0x11 = drowned [code]; 8 in the brood and 9 in the queen and her half [save]. Names of the other modes [open].
- **S:** auxiliary value of the mode. `_ExitHole` writes the 5th argument only when M = 6, 0x78 in certain cases and 0 in the others; `_DoNestAntB` writes the result of `_GetWinner` there [code]. General meaning [hypothesis: target/counter of the mode].
- **Lag of the counters** [save + code]: `_CountAnts` only runs every 64 cycles (`_DoAntSim`, phases `(_Cycle & 0x60) >> 5` = 0 and 2; see [simulacao-visao-geral.md](../regras/simulacao-visao-geral.md), §5.1). In `QUICK2.ANT`, `_CastePopB = [2, 2, 0, 0, 0, 1]` but there are 3 black eggs in list B; indices 1–5 and the totals (`_BpopT = 3`, `_RpopT = 2`) match the recount of the lists plus the yellow ant (`_MeType = 16`, class 2, counted when `_MeMode == 0`) [test `contadores_de_populacao_batem_com_as_listas`]. The yellow ant's colony in the count depends on `_grndTile + 2`, which is not saved [code]; in `QUICK2.ANT` it is black. **On load the counters are recomputed** [observed on the QEMU bench, 2026-10-16]: `QUICK2.ANT` loaded and read from memory has `_CastePopB` = `[3, 2, 0, 0, 0, 1]` and `_CastePopR` = `[4, 1, 0, 0, 0, 1]` (the eggs in the list), and a save with the black worker of list A removed gives `_BpopT` = 2. Loading also sets `_GamePaused` (the loaded game stays paused). See [../../bancada-qemu.md](../../bancada-qemu.md#carregar-um-save-injetado-passos-observados-em-2026-10-16).

### Yard (patches) and points

- `_YMapPopB`, `_YMapPopR` (192 bytes): population per yard patch, **12 × 16**, index `x * 0x10 + y`, with `(x, y) = _CurYardPnt`; `_SimColonies` (`1030:35f8`) writes `min(_BpopT & 0x3ff, 250)` and `min(_RpopT & 0x3ff, 250)` there for the current patch [code]. Since `x * 16` goes up to 176, `x` ranges from 0 to 11 and `y` from 0 to 15; which axis is horizontal on screen has not been verified [hypothesis]. In `QUICK2.ANT`, patch `(11, 8)` (index 184) has 3 and 2, equal to `_BpopT`/`_RpopT` [save].
- `_YMapSeeds` (192 words): seed per patch, index `y * 12 + x` (order swapped relative to `_YMapPop`), passed to `_RandWorld` (`1030:5ab0`) when entering a patch, together with the patch's populations `_YMapPopB/R` [code: `_XferPatch` (`1000:ab90`)].
- The 4-byte `*Pnt` blocks are **pairs of words (x, y)**, not 32-bit integers [code: `_DoLoadInitializations` writes `_MeLocX`/`_MeLocY` into `_YMapPnt` (plane 0), `_AMapPnt` (1), `_BMapPnt` (2) or `_RMapPnt` (3) according to `_MePlane`]. `_CurYardPnt` = current patch (in `QUICK2.ANT`, `(11, 8)`).
- `_GameTime` (4 bytes) is a 32-bit counter: `_DoAntSim` increments the low word and propagates the carry to the high one [code].
- The `Y` prefix in `_YMap*` means yard, not yellow ant [code: indexed by the current patch]. Plane 0 of `_MePlane` corresponds to the yard view [hypothesis].

Impact on the port: the port's save format must be its own (versioned and readable, for example JSON with the same keys). The original `.ANT` is used only as an import, for comparison tests against the original.
